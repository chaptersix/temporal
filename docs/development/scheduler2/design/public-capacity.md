# Public configured buffering

Implemented; independent review and milestone acceptance remain pending. The unchanged public capacity regression failed against the four-slot implementation (0.720s, `/private/tmp/scheduler2-capacity-before.log`). It tests BUFFER_ALL and ALLOW_ALL with limits 2, 5, 1000, 0 and -1.

Reference accounting is `len(Invoker.BufferedStarts)` in `scheduler/generator_tasks.go`. This includes pending starts, tracked running starts and retained completed tracked starts (`invoker.go:recordExecuteResult`, `recordCompletedAction`, `applyCompletedRetention`), but removes acknowledged ALLOW_ALL starts. Nonpositive MaxBufferSize disables automatic dropping. Configuration limits retained ingress, not the number of workflow starts allowed over time. Accepted manual/backfill commands retain authority while waiting for capacity; draining an existing queued candidate transfers occupancy and must not need an additional buffer slot.

The runtime public profile carries live namespace capacity and buffered operation accounting into the pure decision state. The internal profile remains the original four-slot domain for existing bounded proofs/tests. Automatic overflow has an explicit dropped disposition; no start identity or action budget is consumed. Public operation admission no longer rejects merely because four unrelated active records exist. Terminal diagnostic retention is separate from active authority.

The existing immediate pump remains capped at two logical quanta and one physical fallback; no RPC occurs under lock. Existing queue cloning and metadata scans depend on retained cardinality. Increasing public storage capacity does not prove constant metadata work; disabled limits make this an explicit implementation obligation, not a finite-proof consequence. Source review must resolve this distinction before claiming the stronger bounded-work milestone.

The completion callback already carries canonical `ChasmNexusCompletion.CloseTime`; the public adapter validates it on first active application. PublicRuntime retains bounded ten `(operation ID, close timestamp)` memberships. Public occupancy is queue length + persisted Unfinished + completion-membership count; this avoids an added all-operation phase scan. ALLOW_ALL acknowledgment decrements Unfinished and does not enter completed membership. Completion retention is independent from recent-start display. Oldest canonical completion can evict itself, including the latest operation pointer; completed late acknowledgment is then a no-op, while new admission continues. No active operation can be evicted.

Public capacity waiting preserves accepted command/queue authority and retained leases. A physical one-second retry permits a live configuration increase to wake deferred ingress even when no external result remains; the immediate pump cannot spin on this retry. Overflow automatic occurrences advance the disposition cursor and increment BufferDropped, without action identity or budget allocation. BUFFER_ONE policy rejection remains OverlapSkipped rather than configured overflow.
