# WI-018: bounded public transaction work

Status: draft for independent design review; no implementation or acceptance claim. D59's transaction-work requirement remains open. This is a correctness dependency of WI-015 acceptance, not a replacement with M4 measurements. Public MaxBufferSize semantics, including nonpositive limits, remain unchanged.

## Concrete violation and source boundaries

Current two-quantum pumping bounds transitions, not work within them:

| Path | Current cardinality-dependent work | Required replacement |
| --- | --- | --- |
| `component.go:stateFor`, `decision.clone`, `publishTransition` | decode/copy/encode every queued entry; clone PendingStarts | keyed queue frontier and pending-operation index; fixed root summaries |
| `public_projection.go:publishPublicTransition/updatePublicResult/retainPublicActions/publicRecent` | clone all active public actions, scan/sort them | keyed action metadata plus fixed ten-element recent-start and completion windows |
| `public_visibility.go:SearchAttributes` | inspect every action and operation for running count | persisted count updated from the addressed operation's before/after phase and actual RunID presence |
| `coordinator.go:currentEnumerator`, `occurrence.NewPublic` | rebuild accepted spec and scan its term union on repeated quanta | versioned term pages and bounded incremental candidate/exclusion evaluation |
| `component.go:retentionEviction` | inspect every operation for oldest terminal | bounded terminal membership index, never scan active authority |
| `payload_storage.go:collectPayloadBlobs` | read all issuance records and inspect every blob key | transactional reference-count deltas for only changed owners |
| `chasm/tree.go:prepareComponentValue` around1374 | reconstruct every raw-map entry when hydrating root | opt-in lazy keyed collection handle, no enumeration on hydration |
| `tree.go:syncSubComponents` around930/1007 | recurse through clean nodes; MapKeys and full keep/delete set | mutation journal for opt-in collection keys; dirty-node worklist |
| `tree.go:markSubtreeDirty` around426 | walk every descendant on root mutation | distinct local dirty worklist and ancestry invalidation bookkeeping; do not misuse current subtreeIsDirty semantics |
| `tree.go:closeTransactionSerializeNodes`, task update, cleanupTransaction, EachPureTask | walk entire tree or all logical tasks | touched-node serialization/reset; explicit task-bearing-component index and bounded scheduler task set |

`chasm.Map` is an ordinary Go map (`chasm/map.go`). Moving an unbounded slice into that map alone is insufficient. DATA fields avoid decoding untouched payloads, but current collection hydration and tree walks still visit their metadata.

The accepted cold boundary is distinct: SQL `getChasmNodeMap` loads all persisted rows; `MutableStateImpl` computes sizes for all CHASM nodes; `NewTreeFromDB` reconstructs the full node topology once. This design does **not** promise constant cold database IO or whole-record snapshot/replication export. Record those O(N) costs separately under restart evidence. A cache hit or repeated component access is not a new cold load and must not rebuild every collection. Every ordinary mutation after a genuine cold reconstruction must satisfy the hot-work bound, including its first scheduler quantum. The existing global mutable-state size limit is not a proof of that bound and must not be used to cap the public queue silently.

## Minimal coherent representation

### Additive CHASM keyed DATA collection

Introduce an opt-in collection type alongside, not replacing, raw `chasm.Map`. Its persisted collection/entry paths remain explicit CHASM nodes. Its live handle stores the collection node and transaction-local key deltas; `Get(key)`, `Put(key)`, `Delete(key)` touch only that entry. No exported backing map, implicit Range, or whole-key serialization. Existing raw-map hydration/synchronization semantics remain default. A caller that needs traversal must use an explicit persisted index and budget.

The initial use is DATA-only, not an unbounded tree of task-bearing child components. This avoids needing a new cross-execution atomicity contract. Scheduler, Generator and Visibility remain a fixed set of components; queued records, indexed pages, operations, requests, action projections and blobs are individually keyed DATA nodes. Reads must not mutate collection structure or manufacture absent entries.

Use separate dirty concepts: nodes needing structural sync, nodes needing byte serialization, and components whose tasks need validation. A root mutation can invalidate descendant component tasks; current downward `subtreeIsDirty` propagation must not simply be removed. Maintain an explicit component/task-bearing index and validate the relevant components. For the new scheduler layout their count is fixed; DATA descendants need no task validation. Default libraries retain the existing behavior unless independently proven equivalent. Capture dirty-node membership and changes in the transaction; rollback, replication replacement and reload must reset/rebuild indexes correctly. Update immediate-task synchronization, lifecycle/visibility processing, serialization, task cleanup, time skipping and transaction cleanup together; optimizing only one walk is insufficient.

Collection updates feed existing `NodesMutation.UpdatedNodes/DeletedNodes` in the same mutable-state transaction. No asynchronous external store or independently committed child execution is introduced. Deleting a collection with unbounded contents cannot eagerly recurse: logically detach/fence it and drain a bounded cleanup cursor. Closing the schedule atomically revokes authority and its bounded logical tasks; physical DATA cleanup can follow under a fenced maintenance task or existing execution deletion, without admitting work.

### Fixed root control and indexed queue

Root retains counts, sequence numbers, queue index roots, class frontier keys, concrete coordinator lease, generation/revision tokens, and bounded command/effect metadata. Existing ingress cap100 bounds accepted manual/backfill metadata; it must not be confused with configured queue capacity. Public queue records are separately keyed by monotonically assigned sequence. A sequence exhaustion check is explicit identity exhaustion, not a replacement queue-size limit.

Use fixed-fanout radix pages with bounded key width, not an ever-growing root slice or a balanced tree whose root serializes every key. For sequence indexes, uint64 keys give at most16 nibble levels. A time/sequence index needs an explicit bounded-width encoding of signed seconds, nanoseconds and sequence (e.g.160bits/40 nibble levels), preserving ordering across the wide timestamp domain. Each page contains at most16 children and subtree counts. Each point/range-boundary update touches a fixed number of pages independent of N. Persist page size/key width as schema constants; verify counters, not just asymptotic descriptions.

Maintain fixed policy/category indexes: automatic versus explicit manual/backfill, and the finite overlap-policy classes. Derive the first eligible waiter from a fixed number of class frontiers; derive the last eligible cancel/terminate waiter from corresponding tails. This must match current `DrainIndex` and `drain` exactly: selection of a later replacement discards the first eligible predecessor and eligible earlier effect-policy entries, while retaining ordinary intervening waiters. It does **not** discard every predecessor. Prefix/range detachment uses subtree counts for exact counters; detached records are reclaimed incrementally. Expired automatic ranges and policy invalidation require the same summary discipline. No unbounded scan may hide inside a helper named 'frontier'.

A scan-based alternative would need durable snapshot/restart semantics under concurrent arrivals and policy updates and could silently change which replacement wins. Prefer indexes that preserve one atomic logical admission. A bounded cleanup-only quantum can precede service, but must preserve concrete queue leases and class fairness; cleanup cannot starve accepted producers. If an index cannot answer current eligibility exactly, that is a design blocker, not permission to weaken replacement semantics.

### Operation readiness, retention and payload ownership

An unbounded `PendingStarts` map and unbounded root logical StartTask list also violate the gate. Store per-operation wake/phase in keyed records; maintain a bounded-width ready/deadline index and a fixed number of dispatcher logical tasks. A dispatcher snapshots one eligible operation/request under lock, performs its RPC outside lock, and merges by the original execution/operation/wake/chain fence. Retries update one index entry; minimum wake comes from an index root. Preserve fairness among ready operations, real retry horizons, ambiguity retention and identical immutable request bytes. Changing physical delivery envelopes must not authorize a stale logical wake.

Keep public action metadata keyed by operation. On acknowledgment/completion update only that record, then fixed-size ten-element recent-start and canonical-completion windows. Active RunningWorkflows membership and count are keyed/indexed; no active record is reclaimed to satisfy diagnostics retention. Preserve callback-before-ack enrichment and completion-retention self-eviction semantics.

Payload reference counts belong to separate keyed metadata, not the immutable content blob. In the same transaction, diff the fixed set of references owned by the changed issuance/template/carryover record; increment/decrement those counts and delete zero-ref blobs. Deduplicate repeated references within an owner according to a documented ownership invariant. Rollback must restore counts and records together. No periodic full owner scan is part of correctness; an offline audit may scan as diagnostics. Close can detach owners for bounded cleanup while fencing all future issuance.

### Definition preparation is also work

`NewPublic` intentionally removed prototype term/range limits. `currentEnumerator` reconstructs the enumerator from the accepted definition; raw candidate union/exclusion lookup scales with term count. Eight probes therefore do not bound total hot work for a large valid definition. Keep necessary request validation/normalization proportional to the submitted request, but do not repeat whole-definition compilation under every later scheduler mutation.

Persist versioned bounded term pages or a compiled source index. A raw-search continuation may carry current term page/offset, minimum candidate accumulator, and exclusion-validation progress; a handoff is eligible only after the complete union/exclusion computation for that raw boundary finishes. Each quantum processes a schema-fixed number of terms. Definition replacement atomically invalidates the old search continuation by revision and starts new preparation, preserving accepted command authority and old immutable admitted requests. Named preparation stutters must refine the existing one-probe source semantics; do not silently truncate terms or change the calendar horizon, jitter, raw exclusion disposal or compute-limit classification. Existing finite proof remains the reference for its admitted domain; a new refinement obligation covers incremental evaluation. This item must either implement this path or demonstrate an existing independently enforced accepted definition bound sufficient for a declared work formula; a transport maximum alone is not that demonstration.

### Read projections and output-size cost

Describe returns all running workflows and the current action definition, so total response work necessarily scales with required output. Plan P3.4 requires metadata isolation from unrelated carryover/diagnostics and keyed callback isolation; it does not permit dropping required response fields. Keep exact external API output, with no silent pagination. Budget read traversal explicitly per returned running record plus the one requested current action payload; do not load historical issuance payloads, unrelated operations, or sort all actions just to return the bounded recent-ten projection. List/visibility use bounded stored projections and counters.

The fixed work gate applies to scheduler mutation/work quanta and their framework close paths. Full Describe output assembly is a separately measured output-proportional read, just as whole-record cold reconstruction is a separately admitted boundary. This distinction is necessary to retain the required full public API; it does not exempt repeated hot mutation scans. Capture an immutable/versioned projection snapshot outside the mutation critical section if the current engine supports a consistent handoff; that is an optimization to assess, not a prerequisite invented for WI-018. If added, snapshot membership must remain consistent across concurrent changes and retention/release cannot add an unbounded mutation scan. Never claim a fixed bound for whole Describe latency or bytes when response cardinality is unbounded.

## Proposed staged implementation and gates

1. **Instrumentation and smallest witnesses.** Count nodes visited (including clean nodes), collection keys inspected, DATA decode/encode operations and bytes, task validations, and index pages touched across the full handler plus CloseTransaction. Install deterministic test hooks only; exercise a callback, unrelated update, queue handoff, a bounded metadata read, full Describe output, and physical-task delivery at N=0,4,5,1000 and larger disabled-capacity fixtures. Baseline must demonstrate growth in the identified paths. Separate the one true cold reconstruction's counters from each following transaction.
2. **CHASM opt-in collection and worklists.** Add keyed DATA collection, point-delta synchronization and bounded-layout component/task index. Preserve existing raw-map tests and pointer/ancestor invalidation, visibility, task cleanup, time skipping, replication, deletion and rollback semantics. Use poisoned unrelated DATA to show locality, but also count clean metadata visits: absence of decoding alone is insufficient.
3. **Scheduler record/index migration in the local new profile.** Implement bounded root summaries, queue indexes, keyed operation/action/request records and refcounts. Keep old finite-profile decoding and tests; no production routing or existing execution migration. Test index transitions against a simple full-state reference for small exhaustive and larger randomized traces, including updates/expiry/replacement and MaxBufferSize0/negative. Commit counters/indexes/record changes atomically.
4. **Task and projection integration.** Add bounded ready/deadline dispatcher and output-proportional Describe over keyed records; nil-library detached readers must still decode full persisted records with no config, handlers or scheduling. Run exact physical stale/recreated fences and shared public contracts unchanged.
5. **Bound verification and review.** Assert explicit maxima derived from fixed page/key widths, bounded root summaries, fixed logical task count and two pump quanta. Budget includes each schema page and metadata inspection—not only successful work. Assert mutations and encoded root/index byte sizes do not grow with backlog; payload bytes are charged only to the addressed accepted payload. Preserve expected cold-load O(N), full export and output-size costs separately. Repeat after failed publication, shard/cache reload, duplicate delivery, cancellation and clock changes. Run baseline/M4 workload measurements after the count gates pass; measurement alone cannot close D59.

## Count formulas to freeze before implementation acceptance

Use schema constants, not backlog-sized budgets. For a radix page with F=16 children and H=16 sequence levels or H=40 composite-time levels, a point path reads at most H+1 pages; inspecting every child still costs at most F(H+1) key slots. Prefix detach/aggregate uses a fixed number of boundary paths, not a range walk. Let I be the fixed number of maintained policy/time indexes and R the fixed number of record/reference owners changed by one admitted transition; assert a derived bound of the form `C_root + I * C_paths * F * (H+1) + R * C_record`, multiplied by at most two immediate quanta plus the separately counted delivered quantum. Freeze I, C_paths, R and the serialization-byte bound from the final schema/reducer, and fail review if any parameter is computed from queue/operation cardinality. At most one bounded cleanup batch and a fixed term-evaluation batch may be charged as named stutters; neither may hide an all-record walk.

DATA byte accounting has a separate explicit input/output term for the addressed action/result/failure and necessary public response. Require zero unrelated blob decode bytes, bounded control/index page bytes, and exact reference-owner accounting. Compare N=4,5,1000 and larger disabled-limit backlogs against the *same* fixed node/key/page maxima. Wall-clock curves are corroboration, not substitutes for these counters. These are design formulas awaiting concrete API/schema choices, not already measured guarantees.

## Required invariants and non-negotiable review points

- QueueCount + unfinished + ten-completion membership equals configured occupancy; index/subtree counts equal live records after every successful publication.
- Accepted intent remains reachable until an explicit disposition, including MaxBufferSize reduction/disable/re-enable. No arbitrary cap4 or global8MiB substitution.
- Rank/range disposal counters and action budget match the existing decision reference; materialization/refcount cleanup does not become an extra logical admission.
- Current lease belongs to the same concrete candidate until transfer or evidence-backed invalidation; index compaction does not change its identity.
- Per-operation tasks and callbacks retain execution/run/wake/chain fences; stale physical tasks are harmless after close/recreation.
- New collection and index state can be read by `NewDetachedExecution` using the whole persisted record and `NewNilLibrary`; missing nodes fail honestly, never fetch runtime config or fabricate contents. `TestAllNilLibrariesRegistered` and `TestNewNilRegistry_TasksDecodable` remain required.
- Full-state cold DB read/reconstruction, snapshot export, replication snapshot and response-size work are explicitly reported; no repeated per-transaction map hydration is hidden as cold startup.

Open design decisions for independent review are the exact lazy collection API, task-bearing dirty worklist compatibility, output-proportional read isolation (and optional stable snapshot handoff), and queue-index encoding/eligibility proof. These are implementation questions to resolve from source/tests; none authorizes a weaker public contract. WI-015 stays open until the resulting WI-018 gates pass.
