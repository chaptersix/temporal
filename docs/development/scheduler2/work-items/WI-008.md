# WI-008 — Durable manual trigger identity and admission

Status: investigating; depends on WI-007 acceptance. Full M2 remains open.

Independent source inspection establishes these requirements before implementation:

- Reuse CHASM command deduplication (`handler.go:185–207`, engine update at
  `service/history/chasm_engine.go:623–637`), independent of cap4 retained start
  records. Nonempty request IDs are first-success-wins even with a changed body;
  empty IDs denote independent calls. Count/age retention bounds remain explicit
  (`chasm/request_ids.go`); no indefinite dedup claim. Acceptance and request-ID
  recording must share one transaction. Failed publication cannot consume the ID.
- Honor TriggerImmediately.ScheduledTime as workflow identity, not a future timer.
  API v1.64.3 schedule/message.pb.go:918–924 and frontend:4941–4943 establish this;
  V1 workflow.go:546–554 consumes it. Existing CHASM backfiller_tasks.go:239–247
  instead uses component creation time, a parity defect to fix rather than copy.
  Different commands at the same timestamp need distinct operation/start request
  IDs while retaining the documented workflow-ID suffix behavior.
- Manual admission bypasses pause, RemainingActions debit and catchup expiration,
  but obeys overlap policy. See invoker_tasks.go:572,587–588,643–647 and legacy
  workflow.go:854–876,1654–1660. Freeze ALLOW_DUPLICATE workflow reuse for manual
  starts (invoker_tasks.go:689–692). Carryover/completion participation follows
  the admitted policy, including ALLOW_ALL exclusion.
- Resolve explicit overlap override, otherwise schedule policy, otherwise SKIP.
  Unspecified override adopts current policy when transferring accepted pending
  command into the execution queue, matching delayed processTrigger resolution.
  Once queued, preserve identity/policy and sample current template/carryover at
  admission. Automatic cursor advancement must remain independent of manual time.
- Use bounded durable pending commands. Reject capacity exhaustion before accepting
  or recording dedup; accepted commands wait when execution capacity is full.
  Existing CHASM backfiller_tasks.go:107–129 waits and scheduler.go:246–256 rejects
  excessive outstanding backfillers. Legacy full-buffer dropping is a documented
  difference. SKIP/BUFFER_ONE can still legitimately dispose under overlap policy.

Routine choices to settle from implementation evidence: prototype pending capacity
(proposed4), command sequence/identity representation, wake ownership and shared
future backfill fairness. Reuse immutable admission+60s retry horizon, explicitly
stronger/bounded differently from existing CHASM attempt-count behavior. No human
contract decision has emerged from inspection; do not ask for authorization again.

Acceptance must include actual CHASM request-ID dedup/atomic publication, replay
through retention boundaries, same-time distinct commands, supplied future/past
ScheduledTime, all overlap overrides, paused/exhausted manual execution without
budget debit, queue-capacity recovery, selective loading, immutable retry/update,
independent model/oracle, mutation sensitivity and race/lint/review. Public API
routing remains test-only M3 work, with no production selector changes.

Next: resumable backfill fairness, then remaining M2 specification/mapping gates,

is investigation, not evidence of implemented or accepted behavior.
