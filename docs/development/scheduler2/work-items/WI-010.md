## Investigation decisions before implementation

1. **Define the action anchor event and clock.** The reference anchor is the maximum
   of creation, update and action ActualTime (scheduler/scheduler.go:549–560),
   persisted before history truncation. It is not automatically workflow completion
   time, nominal occurrence time or last callback delivery time. Trace the producer
   of ActualTime for tracked and start-only actions and map it to scheduler2's
   admission/acknowledgment phases before choosing a field. Ambiguous starts, late
   acknowledgments, historical backfills and future scheduled manual identities
   distinguish these clocks. Keep the persistent anchor independent of evictable
   operation records and diagnostics; reads must not mutate it.
2. **Specify lifecycle eligibility independently of scheduler work readiness.** A
   capacity-blocked coordinator has work, even when no task is armed. Pending
   manual/backfill commands, queued entries, effects and ambiguous operations need
   an explicit eligibility table. The old held-open predicate only names pause and
   backfill; its generator/invoker integration supplies other behavior. Do not copy
   that predicate alone or infer that every unfinished ALLOW_ALL action holds open.
   Confirm zero idle duration and paused/manual-only behavior from source tests.
3. **Establish recreation ownership.** Determine how CHASM allocates new execution
   references, routes old component references, drops physical envelopes and handles
   concurrent Delete/Update/Create. Give the new incarnation a concrete allocator
   and persistence boundary, not a caller convention. S8 prevents old callbacks
   mutating the new schedule; it does not by itself promise an already-issued
   external start can be canceled by Delete. Record pre-read, pre-RPC and post-RPC
   delete guarantees separately using framework evidence.
4. **Define close mutation rules.** Explicitly decide which control commands reject
   after close and which stale results/tasks become no-ops, preserving idempotent
   first-terminal behavior. Verify close revokes durable scheduling authority and
   that queued physical tasks cannot resurrect it. Do not add an undocumented
   promise that deleting a schedule terminates its started workflows.
5. **Separate definition revision from API conflict/dedup tokens.** Retain accepted
   automatic supersession, historical backfill rebase and queued-policy identity.
   Specify atomic source+policy+budget update or document the local adapter boundary;
   do not claim independent ConfigureGeneration and decision.Update calls are an
   atomic public UpdateSchedule. Public memo/search attributes and response errors
   need their own C10 correspondence work.

These are evidence questions, not a request for a human checkpoint. Resolve routine
choices from framework/reference source, recording explicit divergences; escalate
only a materially ambiguous public contract after that investigation.

## Required discriminating verification

- **Anchor/retention:** admit actions with reordered nominal, actual/admission and
  completion times; evict the record holding the maximum action anchor at cap4;
  verify anchor/deadline never decrease through reload. Repeat with start-only,
  historical backfill, late result, clock rollback, and duplicate callback. Mutant:
  derive anchor only from retained records, or advance it on every callback.
- **Idle progress:** real Node physical delivery and commit/reload at deadline−1,
  deadline and deadline+1; update/action moves deadline later, stale old timer
  drops while replacement remains; stable deadline eventually closes. Duplicate
  wakes must not accumulate obligations. Failed rearm/close publication preserves
  prior state and physical obligations. Include exhausted budget, empty source,
  paused manual-only, accepted blocked commands, queue, effects and ambiguity.
  Model L3 with explicit eventual stability, task fairness and successful commit
  assumptions; do not infer it from a safety-only finite exploration.
- **Delete/recreate:** real execution A→close→B under the same schedule name;
  deliver A's callback, acknowledgment, start/effect response and physical work,
  expiry and idle tasks to their original refs after B exists. B's complete state,
  payloads and task obligations stay unchanged. Include same numeric tokens and
  occurrence times in both incarnations, in-flight read/RPC barriers and failed
  delete publication. A malformed old payload must not force loading B's payload.
- **Updates:** queued candidate keeps identity/policy but uses current definition
  and carryover at admission; already admitted start/effect bytes remain identical.
  Exercise paused/unpaused, budget replacement without a second debit, policy
  changes while a lease or effect is pending, historical range rebase and jittered
  automatic pending supersession. Fail publication at each update/handoff boundary;
  verify cursor/lease/task/request atomicity and stale task fencing.
- **Evidence boundaries:** run focused and race tests with test_dep, saved replays,

## D51 terminal authority and first implementation slice

Framework inspection establishes that closed root reads/unspecified-intent updates
remain possible, and task processing may access retained closed executions. A
persisted Closed flag is therefore required independently of CHASM lifecycle state.
Close/Terminate is idempotent, preserves historical records, disarms coordinator and
legacy control metadata, and clears pending issuance metadata. New/non-deduplicated closed controls
return NotFound before validation/payload loading; results and retired deliveries
are no-ops. Request snapshots and task validators check the root fence first.
The original implementation also maps Closed to LifecycleCompleted; History's
DeleteExecution separately records framework TERMINATED and queues physical removal.

Authorization ends at the locked request snapshot boundary. A snapshot authorized
before close can still be issued outside the lock, including after close commits;
its exact-run result is ignored. There is no promise that delete cancels an issued
or already-authorized workflow start, nor that it terminates child workflows.
History allocates a fresh UUID before invoking a recreate factory; asynchronous
refs retain their exact RunID. An old ref must resolve old retained state or NotFound,
never fall through to a replacement's current-run identity.
