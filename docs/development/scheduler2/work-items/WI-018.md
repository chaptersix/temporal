# WI-018 — Bound public scheduler transaction work

Status: implementing bounded public runtime; indexed queue slice accepted, operation/dispatcher/projection and persisted calendar integration remain open. Milestone dependency: WI-015/M3 acceptance requires this item; M4 measurements also depend on its instrumentation. User authorization remains local execution, no pushes, production routing, rollout or migration.

## Contract and dependencies

Preserve D59 and accepted M2 admission, identity, capacity/fairness, payload ownership, rollback and stale-task guarantees while removing cardinality-dependent work from ordinary public transactions. Public configured capacity, including disabled MaxBufferSize, remains supported. Two coordinator quanta alone are insufficient.

Depends on accepted CHASM/WI-001 guarantees and M2 contracts, plus current WI-015 implemented public execution/capacity/timestamp checkpoints. **Does not depend on WI-015 acceptance**, avoiding a cycle. The proposed design is `../design/bounded-public-work.md`; independent design review by api_seam/oracle_review is required before implementation acceptance. Parent owns central plan/ledger/acceptance.

## Ownership and implementation order

- Draft/source audit: proof_review.
- Integrator: parent; assigns implementation ownership after independent design review.
- Proposed independent surfaces: CHASM additive keyed collection/worklists; scheduler indexes/refcounts/dispatcher; output-proportional read isolation and detached-reader compatibility. No overlapping edits without explicit owner coordination.

1. Add deterministic full-transaction visitation/decode/encode/task counters and failing backlog-neighbor witnesses.
2. Implement opt-in lazy/delta DATA collections and worklists while retaining default raw-map semantics.
3. Implement fixed-root scheduler indexes/summaries, bounded task readiness and reference ownership changes.
4. Implement bounded stored projections and output-proportional required Describe reads; retain exact external API and offline reader behavior. Assess consistent snapshot handoff outside the mutation critical section as an optional optimization.
5. Verify count bounds, model/reference equivalence, rollback/reload, actual physical fences and unchanged shared contracts; independently review final source/evidence.
