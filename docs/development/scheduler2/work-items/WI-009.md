# WI-009 — Resumable backfills and fair capacity acquisition

Status: investigating; depends on accepted WI-008. Full M2 remains open.

Source-backed direction from independent inspection:

- Cap4 durable active backfill requests, accepted atomically with existing CHASM
  request-ID dedup. Independent request sequences distinguish overlapping ranges.
  Reject overload before acceptance; never capacity-drop accepted occurrences.
  Existing scheduler.go:246–256 rejects excess backfillers; backfiller_tasks.go:107–129
  and its full-buffer test preserve progress while waiting.
- Inclusive start/end, jittered actual time <= end. Legacy workflow.go:557–563 and
  CHASM backfiller_tasks.go:180–194 deliberately include start; test:169–204 covers
  equal start/end. API v1.64.3 schedule/message.pb.go:975–980 still says exclusive
  start: record this comment discrepancy. Use an explicit lower-bound predicate,
  not a blind1ms subtraction that mishandles fractional timestamps.
- Persist nominal search/disposition cursors and complete pending candidate, using
  WI-002's separate progress concepts. Capacity wait cannot advance disposition.
  Handoff/disposition and cursor/task publication are atomic. Bounded scan Yield
  is not exhaustion. Request completion means durable handoff/disposition finished,
  not all generated workflow executions completed (backfiller_tasks.go:145–160).
- Backfill uses manual pause/budget/catchup bypass, overlap behavior and ALLOW_ALL
  exclusion from carryover. Distinguish backfill occurrence identity from trigger
  sequence and automatic cursor. Freeze queued identity/policy, template at admission.
- Both existing implementations enumerate current definition on later batches
  (backfiller_tasks.go:188–198; legacy workflow.go:957–964). Preserve that behavior:
  rebase unadmitted search after last disposed nominal, never execution-now for a
  historical range. Define stability assumptions and pending jitter/update semantics
  before implementing; existing occurrence.Update(now) cannot blindly serve this.

The plan's C11/L2 requires more than fair task delivery. Introduce persisted bounded
round-robin arbitration among accepted manual, backfill and automatic ingress, and
among active backfills. A grant performs one handoff/disposition or bounded scan
quantum; skip empty/unready classes. Protect eligible queue drain from repeated
ALLOW_ALL direct admissions taking every freed slot. Every competing admission path
must honor arbitration; existing per-backfiller integer shares and V1 half-buffer
loops do not prove sustained-ingress fairness.

WI-008 full-queue waits remain; an entitlement governs who consumes newly available
capacity. This supersedes absence of arbitration, not committed intents. ALLOW_ALL
bypasses overlap but does not obtain unlimited priority over accepted ingress.
Actual arbiter state/interfaces and transaction limits require design review before
implementation; this investigation is not an accepted fairness implementation.

L2 assumptions: fair task delivery, eventual successful publication, bounded source
work, definition stability sufficient for finite enumeration, and recurring adequate
queue/operation capacity including necessary tracked completions. Sustained new
manual/automatic arrivals cannot steal grants. No progress guarantee applies while
external operations occupy capacity forever. Finite recovery traces prove reachability,
not infinite-execution liveness; distinguish model fairness claims accordingly.

Acceptance: range/jitter boundaries, cursor/update rebasing, capacity-fault publication,
identity/dedup, all manual overlap semantics, independent oracle/model, sustained
competition witnesses/liveness assumptions, bounded work/state, race/lint/mutations,
and independent review. M2 specification/mapping and M3/M4 gates remain afterward.
No production routing, migration, rollout, remote execution or pushes.
