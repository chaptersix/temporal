# WI-007 — Durable cancel and terminate overlap effects

Status: implementing; WI-006 accepted at0941e0b58. Full M2 remains open.

Implement CANCEL_OTHER and TERMINATE_OTHER against the single tracked blocking
operation, including delayed binding while its start is Pending/Ambiguous. Effects
need their own durable identity, frozen request and retry state; accepting the
policy enum without the external-effect protocol does not satisfy this item.

Source-backed contract proposal, reviewed independently:

- Freeze WorkflowID and FirstExecutionRunId; leave RunId empty so History resolves
  the current run of that chain. Never issue against WorkflowID alone. Existing
  invoker_tasks.go:771–805 and history/api/requestcancelworkflow/api.go:31–80,
  history/api/terminateworkflow/api.go:32–78 establish fencing behavior.
- RPC success, already-closed or NotFound does not release scheduler occupancy,
  synthesize completion or change carryover. Matching completion evidence does.
  Cancellation acceptance is a request; even termination waits for observed close
  in service/worker/scheduler/workflow.go:1835–1860.
- Terminate dominates future cancel issuance. In-flight cancel results cannot
  suppress a distinct terminate intent (invoker_tasks.go:604–609).
- Key effects by incarnation/target-operation/kind, separate from start IDs. Freeze
  namespace/workflow/chain/reason/identity. Cancel can carry its own RequestId;
  terminate has no equivalent remote dedup field and relies on chain fencing and
  idempotent target state. Do not claim exactly-once physical requests.
- Pending/Ambiguous targets without ChainID retain the queued waiter and desired
  effect but emit no unfenced RPC. Later acknowledgment binds the immutable target
  and creates an executable effect. No refund/discard of committed start intent.

Prototype limits to finalize before implementation: at most two effect records for
one blocker (cancel/terminate), one effect executor permit, bounded horizon/backoff,
coalesced duplicate demand. Timeout/context cancellation retains unknown acceptance;
expiry stops issuance without clearing blocker. Completion invalidates target effects;
stale responses cannot affect a successor. Queue cap4 overflow drops new automatic
arrival without creating an effect. Existing admitted accounting remains unchanged.

Explicit differences requiring recorded decisions: legacy ProcessBuffer:91–121 can
replace an unstarted selected candidate; a committed redesign Pending intent stays
immutable. Decide FIFO treatment of unadmitted queued cancel/terminate candidates.
Durable effect retries strengthen current CHASM best-effort effect handling
(invoker_tasks.go:317). The retry horizon starts when the fenced immutable request
is bound, rather than expiring while an unknown chain is still an external wait.

Acceptance: independent effect model/mapping, lost acknowledgment and retry identity,
chain replacement fences, early completion, cancel/terminate race and supersession,
unknown target binding, limits/recovery, immutable requests across updates, stale
result/physical task handling, failed publication/restart, current carryover semantics,

Afterward: manual trigger identity/deduplication and resumable backfill fairness,

## D39–D42 implementation agreement

D39: queue capacity4; CANCEL_OTHER/TERMINATE_OTHER enqueue while committed blocker
exists, without debit. At free drain, filter currently ineligible entries first;
first eligible becomes selected, any later cancel/terminate replaces that unadmitted
selection, counted as OverlapSuperseded without debit. Intervening BUFFER entries
remain ordered. Effect terminate dominance does not govern candidate selection:
later cancel may replace earlier terminate. This follows ProcessBuffer replacement;
filter-before-selection is an explicit extension of WI-005 catchup behavior versus
legacy selection-before-catchup. Committed Pending/Ambiguous work is never replaced.
D40: at most two effect records (cancel/terminate) for the current tracked blocker.
Desired policy derives only from accepted queued entries; full-buffer overflow creates
no demand. Terminate supersedes future cancel issuance, including unbound cancel.
Effect IDs are target start-operation ID plus /cancel or /terminate. Unknown chain
waits without a task; later evidence binds immutable namespace/workflow/first-run
fence/reason/identity. Bound deadline is now+60s, backoff1s, one effect executor permit.
D41: success settles accepted effect; NotFound settles no-target retry obligation,
without asserting successful cancellation or completion. Other errors retry boundedly;
expiry retains ambiguity, late success/NotFound may settle. No effect response releases
blocker, changes budget/count/carryover or enables successor by itself. Matching
workflow completion clears target effects; old/superseded results are no-ops.
D42: effect metadata (max2) is root control state; frozen request payloads are separate
DATA entries. Task validation reads metadata only, issuance rechecks target/effect
and clones request. Queue/result transitions, effect binding/payload/task publication
are one CHASM transaction. Root policy updates cannot rewrite queued policy or frozen
effects. Accepted effect demand remains until target completion; current pause or
budget does not retroactively undo a queued overlap request. No broad DB-read claim.

Integrator owns shared implementation/proto and existing-test adaptations. Independent
model owns model/effects; tests own new effects test/replay files; reviewer is read-only.
No human contract decision remains; local-only authorization unchanged.
