# WI-006 — Keyed dispatch and ALLOW_ALL

Status: proposed; depends on WI-005 acceptance. Full M2 remains open.

The next coherent policy slice needs keyed operation dispatch, not enum acceptance
alone. Current State.Operation, Scheduler.state and StartHandler.Validate select
only the latest operation; admitting another would invalidate older pending tasks.
Persist each operation's resolved admission policy. Keep current bounded records,
immutable retry identity/request and per-operation deadlines. Older keyed pending
or ambiguous operations must still accept matching acknowledgments/completions.

Source-backed intended contracts (finalize before implementation):

- ALLOW_ALL ignores non-ALLOW_ALL occupancy and may bypass its waiting queue.
  This is an explicit extension to D32's FIFO rule for buffering policies, supported
  by service/worker/scheduler/buffer.go:61–70. Non-ALLOW_ALL work still serializes
  independently; admitted ALLOW_ALL work does not become its running blocker.
- Request snapshots clear LastCompletionResult and ContinuedFailure without loading
  carryover. Frozen admission policy, not current Root.Policy, decides this behavior.
  Sources: chasm/lib/scheduler/internal/overlap.go:20–23 and invoker_tasks.go:692–705.
- An acknowledged ALLOW_ALL start becomes a reclaimable start-only terminal record;
  do not wait for its workflow completion. Preserve at-most-once started accounting.
  Early callbacks settle the intent once but never mutate carryover or pause state.
  Sources: invoker.go:217–249 and completion.go:188–232. Late callbacks after settled
  start-only retention are harmless; they do not recover unrelated carryover state.
- Retain cap4 operation records. Never evict Pending/Ambiguous intents. When no
  reclaimable record exists, automatic ingress has a counted capacity-drop disposition
  with cursor advance and no debit. This is an explicit bounded-prototype overload
  boundary, not a claim of unlimited production ALLOW_ALL capacity. Verify recovery
  after a successful acknowledgment makes a record reclaimable.

Required evidence: independent policy/identity model, deterministic cases and Rapid
commands for multiple unresolved starts, all4 saturation/recovery, mixed policies,
old keyed retry/ack/callback after later admissions, immutable retry snapshot through
updates, no ALLOW_ALL carryover/pause participation, failed publication/restart,
stale physical tasks, payload isolation, source mutations, race/lint and review.

One local executor permit remains a separate issuance limit; concurrent durable
intents need not issue simultaneous RPCs to demonstrate correct keyed dispatch.
Manual/backfill identity/fairness and cancel/terminate effect protocols remain later
M2 work. No public routing, rollout or migration is authorized by this item.

## Independent contract review refinements

Capacity-blocked drain: distinguish new automatic capacity-drop from existing queue
capacity-wait. Retain accepted queued identities without debit when all records are
unreclaimable. Suppress a drain retry loop while capacity-blocked; any keyed ack or
early completion that makes a record reclaimable must re-arm drain. Ineligible
pause/budget/catchup disposal still proceeds without needing an operation slot.
This is a bounded-prototype overload contract, not source equivalence.

Keyed results: lookup incarnation+operation ID, independent of latest admission.
Each retained Pending/Ambiguous operation accepts matching chain evidence and
counts its own first start once. Frozen policy controls tracking forever. Keep
non-ALLOW_ALL occupancy owner separate; an older ALLOW_ALL acknowledgment cannot
clear a newer blocking action. Start-only terminal means the start intent is settled,
not that the workflow completed; preserve that distinction in projections/API work.
Bound-chain conflicts remain errors without mutation; retained duplicate/evicted
old results are no-ops. Early completion settles the same intent/accounting once.

Additional references: invoker.go:284–301 (early completion),413–418 (running filter);
scheduler.go:653–683 (bounded start-only history/generator wake); completion.go:120–128
(late start-only callback lookup miss). Independent reviewers found no need for a
human material-contract decision; implementation must cover the added wakeup edge.
