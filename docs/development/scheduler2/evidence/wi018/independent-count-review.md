# Independent secondary count-trie review

Reviewer: api_seam. Reviewed frozen count.go/count_test.go, then author followups clarifying byte counters and adding reference-exhaustion rollback. No blocking source finding for this standalone prototype. No persistence adapter/runtime enablement or WI018 acceptance is implied.

Canonical Patricia structure is defined by the first differing key bit and the minimum/left representative key. Bit positions strictly increase down paths, bounded by96; leaf multiplicity is positive. Immutable node identity includes full representative key, bit, multiplicity and child IDs. Interning reuses existing canonical content only after exact equality; every newly interned parent retains child ownership once. Each Update retains its returned owned root before releasing the caller's prior root. Untouched sibling roots therefore survive release, while only obsolete path nodes can recursively disappear. Fork adds one explicit external owner. Callers must hold an owned root and serialize store access; arbitrary fabricated/unowned root IDs are not supported.

Rollback is staged: reads use the overlay before committed nodes, reference/count overflow errors return original root and discard overlay. Verified the new failure tests cover both Fork reference exhaustion and Update failing on a shared-child retain after staging new left pages, comparing the entire committed map. Count overflow during new branch construction and missing deletion already have unchanged-store tests. No new persistent writes occur before final application; future CHASM integration must make all these changes one actual transaction.

CountBefore is strictly less-than: outside a compressed common prefix, comparing the representative key determines whether the entire subtree contributes; inside, right traversal adds only the left count. Valid subtree counts bound accumulation by root total. Full-width adversarial paths, equal keys and multiplicities are checked, not just sequential low-byte insertion. Chronological encoding correspondence is supplied by the separate TimeKey prefix contract; this store accepts all96-bit keys and does not itself validate public timestamps.

For H=97 nodes on a maximal point path, change reads at most2H map lookups; branch reads at most4(H-1); interning at most2H; new parent-child retains at most4(H-1); final root retain at most2; old path/sibling release at most2(2H-1). Total is below16H. Releases are at most2H, and interned canonical byte buffers at most86H. Changed-entry writes have the conservative8H test ceiling. These formulas apply to a valid trie and point replacement with preserved sibling ownership. They do not bound dropping a whole uniquely owned subtree: a future bulk-release API must use incremental cleanup, not call recursive release and inherit this claim.

EncodedBytes now explicitly means canonical hash-input bytes. It excludes refcount-only updates and is not committed mutation bytes. EncodedSize is94 bytes per canonical node plus reference metadata only; hash keys/CHASM paths/envelopes, DB and Go allocation overhead are excluded. A future mutation-value bound can conservatively charge94×Writes plus bare keys and actual framework overhead. Storage tests with10000 distinct keys demonstrate19999 canonical nodes, not aggregate mutable-state capacity proof.
