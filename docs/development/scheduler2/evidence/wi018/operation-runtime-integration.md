## Concrete schema

Add a public operation-layout version discriminator and fixed OperationControl to RootState. Preserve these through wholesale root replacement exactly like IndexedQueue. Fields: NextOperationSequence, NextReadySequence, OperationCount, PendingCount, RunningCount; two DispatchSlot values; at most ten RecentStart entries; at most ten Completed entries. Each window entry contains operation ID and its comparison timestamp; recent entries also retain the result projection or point to a keyed ActionRecord. Stable ties use immutable action-admission sequence for recent starts and completion-arrival sequence for completions. Overflow is checked before any publication.

DATA collections: OperationRecords[operationID] -> existing OperationState plus admission sequence, current ready sequence, logical wake revision and optional retirement index key; RequestRecords[operationID] -> existing Payload skeleton with action/result/failure refs; ActionRecords[operationID] -> PublicAction plus immutable admission sequence and operation-owned/recent-owned membership bits; BlobRecords[contentID] -> immutable Payload; BlobReferences[contentID] -> uint64 owner count; OperationPages -> shared queueindex backend pages. Running membership can use a dedicated SequenceIndex keyed by admission sequence. A sequence-to-operation DATA locator is needed for every index identity; put it in one OperationIdentity record keyed by admission sequence, retained while operation/action/index ownership exists. Do not use digest truncation as an identity.

Keep completed metadata until the existing close-time ten-window evicts it. PHASE_START_ONLY reclamation keeps current public rule: at new admission with OperationCount >=4, reclaim at most one existing StartOnly record, ordered by old signed int64 Nominal then lexicographic operation ID. Other active or ambiguous records are never candidates. The threshold4 is this existing retirement trigger, not an operation capacity cap. Fixed recent-ten ownership may retain an action after its operation is evicted. Removing an operation clears only its action ownership; remove the action/locator only when no recent ownership remains. Late acknowledgment after an operation was actually evicted stays ignored, as today. Callback-before-ack can enrich a retained completed action, without returning it to Running.

Capacity continues to be logical QueueLength + Unfinished + len(Completed), with MaxBuffer <=0 unlimited. Lowering a limit does not reclaim accepted work. RunningCount is precisely the count of records with phase Started AND nonempty acknowledged RunID, not Unfinished. Derive delta from the addressed record before/after; repeated callbacks/acknowledgments have zero duplicate delta. PendingCount means decision.Wake exists, including claimed entries; claims are not removed from pending occupancy.

## Index adapters and explicit missing primitive

Reuse CountBatch and the existing CHASM DataMap backend, with disjoint fixed16-byte owner IDs for readiness, running and StartOnly retirement. All per-transition edits share one staged batch and commit with control/records. SequenceIndex supports fixed-width sequence keys with 96-bit time summaries, not arbitrary string sorting or chronological extrema directly. Do not pretend SequenceExtreme is a minimum-time operation: it returns the minimum/maximum sequence satisfying a lower-time predicate.

For readiness use original canonical CountKey(wake) and monotonically increasing fairness sequence. index_finish is assigned SequenceEarliest(index), returning lexicographic minimum (time, sequence) through fixed-depth count-summary minimum and outer descent. This gives both the next wake and exact ready-time-first selection; the dispatcher compares returned time to now. It must validate the touched count/outer edges and preserve shared batch failure behavior. SequenceFirstDue ordered by sequence across all due timestamps would change the documented contract and is not selected. Until the primitive is independently verified, dispatcher activation waits; no scan fallback.

StartOnly retirement requires exact old signed int64 Nominal then lexicographic ID, not admission order. Source decision.startOperation builds ID as common Incarnation plus automatic/<int64>, manual/<uint64>, or backfill/<uint64>/<int64-or-RFC3339Nano>, then /action/start. Within one incarnation strip the identical prefix. Public supported timestamp years and decimal integer widths bound this suffix to73 ASCII bytes (backfill9 + uint64 20 + slash1 + RFC3339Nano30 + /action/start13). An 80-byte zero-padded suffix preserves lexicographic order, since these strings contain no zero bytes; prepend sign-biased8-byte legacy Nominal. A fixed88-byte ordered trie therefore gives a maximum704-bit path without a new public restriction. This does require a separate reviewed fixed-key minimum index (current SequenceIndex's uint64 identity is insufficient). Preserve the existing legacy Nominal comparison even for wide NominalTime; do not silently fix that ordering in this slice. Validate the suffix derivation and maximum at construction; finite custom-incarnation tests remain separate. This is an implementation dependency, not a material user contract decision.

## Fixed dispatcher protocol

DispatchSlot fields: generation, selected ID, selected ready sequence, selected logical wake revision, claim expiry, armed deadline. One start slot and one effect slot preserve separate concurrency classes. Effects need only inspect their two fixed root entries; no large effect index is needed. At most two dispatch logical tasks plus two pure recovery wakes; existing fixed coordinator/generator/idle tasks remain separately counted. No per-operation logical StartTask remains for this profile.

Acquire the existing local permit before a short claim transaction. Derive recovery expiry from the actual physical context deadline remaining at claim, converted to execution time; if no positive duration remains, do not claim or issue. Remove readiness membership, write generation-fenced claim and its recovery wake, then expose a detached immutable snapshot only after successful commit. If read/assembly/publication fails, no RPC is issued. The RPC snapshot contains original execution incarnation, operation ID, request bytes, chain fence, wake revision and slot generation.

Positive acknowledgments/callbacks reconcile operation authority even after a claim expires. A late negative result can alter retry scheduling only while claim generation and wake revision still match. Releasing an old claim cannot clear a replacement slot. Expiry requeues a still-eligible operation with fresh fairness sequence and current due time; preserve operation RetryAt/Deadline semantics rather than extending issuance authority. Existing overdue-expiration behavior is applied before exposing a request. New arrivals cannot overtake older due time/fairness identities indefinitely. Clock rollback retains future readiness; time skipping cannot skip claims/recovery authority. Close or incarnation mismatch cancels all issuance, including stale physical envelopes after recreation.

## Payload owner delta transaction

Owners are exactly public action definition (one action ref), generator definition (one action ref), each immutable request (up to three refs), and carryover (up to two refs). Count distinct nonempty references per owner, not raw field multiplicity. A new request owns its admitted references even if current template/carryover later changes. Never rewrite RequestRecords on acknowledgments, retries or unrelated updates; terminal transition releases its owner once. Effects own small frozen RPC skeleton bytes directly and do not own action blobs.

Introduce prepareOwnerChanges(ctx, []OwnerChange) -> immutable BlobDeltaPlan, where each change includes owner key, exact old/new reference tuples and expected old owner revision/value. Coalesce counts by content ID; preflight missing referenced bytes, identity collision, underflow and overflow before writes. New blob bytes and count deltas, request/definition/carryover replacement and zero-count deletion publish atomically. Net-zero references do not delete/recreate content. No decoder or hash touches unrelated blobs.

For a conservative fixed mutation envelope allow at most six changed owners: three request owners (addressed plus up to two retention victims), public definition, generator definition and carryover; each tuple has at most three references. Thus at most36 old/new reference visits, at most36 distinct counter point accesses, and no owner scan. Current ordinary operation transition usually changes fewer owners. Reject exceeding this internal envelope as an implementation error; split independently authorized batch work into existing bounded quanta rather than rejecting a valid user request. Close leaves all owners and counts retained for existing whole-execution deletion, with authority revoked immediately.
