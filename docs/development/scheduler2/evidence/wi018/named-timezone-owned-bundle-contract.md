# Named timezone owned source proposal

Status: root approved steps1–2; owned asset and isolated Unix source/cache engine implemented and frozen in named-timezone-source/manifest.json. Shared runtime wiring and native Windows Local remain separate gates. No resolver routing or prior prepared evaluator/codec edits.

That package's generated zzipdata.go holds the exact byte string used by the embedded loader; it is not exposed by a supported runtime API. Reading the toolchain source at development/build verification time is supported and requires no unsafe, reflection, linkname, or runtime private-symbol access.

Repository production sources contain no assignment to time.Local or mutation of TZ/ZONEINFO found in the audit. ## Owned bundle mechanism

Check in the exact extracted zip under a scheduler2 internal timezone-source package, with Go BSD attribution/license and a provenance manifest. A small development generator parses the selected toolchain's zzipdata.go using go/parser and strconv.Unquote, verifies a single string constant, and emits the asset plus hashes. This generator never runs inside CHASM mutation or server request resolution. Avoid copying the giant Go escaped source string into application source.

Add a normal test that reads runtime.GOROOT()/src/time/tzdata/zzipdata.go, extracts its actual literal, and compares it byte-for-byte to the checked-in asset. This gate also verifies the expected current Go time source fingerprints or requires a reviewed refresh when loader/parser source changes. It must fail, not silently skip, when the build/test toolchain lacks the required source. Runtime deployment does not need GOROOT files for embedded fallback. Custom developer toolchains must pass the same parity gate; a version string alone is insufficient.

Use an indexed immutable reader over the trusted owned zip; return fresh source byte copies. This index is built outside mutations. For arbitrary ZONEINFO/GOROOT zip files, preserve Go's stored-entry loader semantics (including unsupported compression, first duplicate-name match, ignored CRC, local-header checks and error precedence); archive/zip's stricter validation/decompression must not silently replace them. All advertised allocation sizes must be checked against available file bytes before allocation. No new TZif byte/transition caps. The existing Go directory-file read limit is source-specific behavior, not a new custom-TZif limit.

## Resolution and cache

Separate a process source environment from per-builder result caches. The process source environment owns once-captured ZONEINFO and once-resolved Local. A per-builder resolver uses existing common/cache.New(1000, Options{TTL:24*time.Hour}) with the same default real clock and injectable test clock. Reuse its precise boundary/eviction behavior rather than implement a new TTL map. Cache successes and errors under the exact name; custom nonnil byte input bypasses this cache, including allocated-empty data. Concurrent cache misses retain the legacy permissible duplicate load/last put behavior; do not introduce new singleflight authority.

Resolve empty/UTC to canonical UTC before source access. Resolve Local through the process-local once result (a cache expiration does not reread system Local). Other names reject double-dot substrings or initial slash/backslash, then lazily capture ZONEINFO. Search captured override directory/zip, platform sources in actual order, owned embedded bundle, and finally the runtime GOROOT zip. Errors preserve actual implementation precedence. In particular, current LoadLocation has a scope subtlety: a readable invalid ZONEINFO blob's parser error is not retained by its outer firstErr assignment; the read error variable there is nil. The platform loader does retain parse errors. Differential tests must preserve this distinction rather than infer behavior from the documentation list.

A successful resolution returns immutable exact source bytes (or explicit UTC), semantic prepared snapshot, source kind/path and byte hash, and the explicit resolvedAt used by PrepareTimezone. Sample the clock immediately before preparation outside the CHASM callback. Cache reuse preserves that original instant/cache tuple; a refreshed load samples a new instant and creates a new snapshot. Staging persists this input and instant. No replay consults filesystem, environment, wall clock or global time.Location.

For Unix Local, absence of TZ loads localtime from /etc with embedded/GOROOT fallback; empty TZ yields UTC; strip one leading colon; absolute paths load directly; other nonempty non-UTC names use platform/embedded/GOROOT without ZONEINFO; failures become UTC. Local rules are resolved once for the process source environment, not once per calendar generation. Local source naming is diagnostic; semantic identity is actual bytes plus seeded cache behavior.

## Shared process capture and stated history boundary

Root resolved the repository startup design: introduce one shared builder/provider source environment, with process-immutable TZ/ZONEINFO as an explicit deployment assumption supported by the production-source audit (no mutation found). Capture at the shared provider initialization boundary and supply the same source environment to all new prepared builders; never create an independent Local owner per builder. Once a Local snapshot is first resolved by this provider, reuse its exact input, initialization year and cache seed for process lifetime. Standard named cache entries still refresh every24hours.

This does not prove arbitrary prior standard-library cache history equivalence: the public APIs cannot recover an already initialized Local's original bytes/cache seed if files changed, nor a prior ZONEINFO capture followed by mutation. A shared startup boundary must be wired and verified before activation, with its exact immutable-environment/history assumption recorded. Do not claim that reopening the same Local path or using a new sync.Once reconstructs inaccessible history. No new public ban on Local or accepted custom timezone bytes is introduced. Synthetic process environments and cold subprocesses establish the scoped parity that is actually testable.

## Supported Windows provider reconstruction

Current Go Windows has no platform source directories. Named lookup uses captured ZONEINFO, embedded data, then GOROOT. Local ignores Unix TZ and calls the exported syscall.GetTimeZoneInformation. On error it becomes UTC. The provider can call the same supported API once at the shared Local capture boundary and retain the complete Timezoneinformation record plus explicit UTC initialization year. A platform-neutral transformation of that native record permits deterministic Linux/Darwin tests and Windows cross-builds.

Mirror initLocalFromTZI exactly: StandardDate.Month==0 means one fixed zone with offset -int(Bias)*60, ignoring StandardBias, one alpha transition and alpha/omega cache. Otherwise standard offset is -int(Bias+StandardBias)*60, daylight offset -int(Bias+DaylightBias)*60 (the additions occur in signed32-bit native fields before int conversion). Derive week/day civil transitions by the same normalized UTC Date calculation; order the two dates by month; emit exactly400 transitions for initializationYear-100 through initializationYear+99. Preserve first-zone selection outside that range, no POSIX extension, and no daylight lookup cache. Do not substitute IANA/CLDR historical rules: Go itself applies this year's Windows rules over that200-year window.

Go additionally computes abbreviations from its Windows table and registry via localized MUI names/fallback capitals. The calendar evaluator does not observe names or isDST, only offsets, interval boundaries, Date normalization and cache semantics. Preserve the full native source record for identity/reconstruction and document abbreviation computation as nonsemantic to this private capability, not as a claim to return a time.Location with equivalent formatting.

Native signed32-bit minute biases can produce second offsets outside signed32-bit TZif range. Therefore a synthetic TZif is not an exact general reconstruction and current89-byte TZif codec cannot blindly encode this variant. Introduce a distinct native prepared-source format and a versioned fixed header/page codec with signed64-bit offsets when implementing Windows; retain format1 decoding for existing TZif snapshots. Fingerprint the actual native offsets/transitions/cache plus initialization year and source-format marker. Persist the native input separately from fixed control, just as TZif input is separate; no unsupported-bias cap or forcedUTC fallback. This is a representation extension, requiring review and explicit byte-bound recalculation after the current persisted checkpoint is released.

Windows source/API capture plus pure native transformation, cross-compilation, northern/southern/no-DST rules, first/last transition boundaries, ignored StandardBias, arithmetic extremes and error-toUTC tests are required before runtime activation. A real Windows subprocess differential remains a platform evidence gate; a macOS cross-build alone does not claim it.

## Offset-width audit before native implementation

Current preparedTZTransition.offset, PreparedTimezone.first, cache.offset and lookup return use Go int; wall/date convert to int64 before addition/subtraction. TZif parsing intentionally sign-extends int32 into int. The TZif semantic fingerprint already encodes cache.offset in64bits and hashes raw source bytes. POSIX offsets are grammar-bounded to608399 seconds (default daylight may add3600); those widths need no new public range restriction. Current format1 serializes first/cache/rules/page offsets as signed32bits, which is sufficient for TZif but not native Windows biases.

The native variant must explicitly normalize the source platform's Go int arithmetic before fingerprinting: Bias+StandardBias is signed32-bit addition, followed by conversion to native int, unary minus and multiplication by60 in native width. Record the source word width in native source identity if supporting32-bit runtimes; do not reinterpret a stored native snapshot with the replay host's width. Widen transition/cache/first and lookup results to int64 in the shared pure evaluator, with TZif and POSIX conversion at their existing input boundaries. Preserve format1 byte emission/decoding for TZif; native format2 uses signed64bit first/cache/transition offsets and its own fixed size/marker. Pure wall/date already perform int64 arithmetic, so audit conversions and fingerprint/page encoding rather than truncating native offsets to fit format1. The native rules have no POSIX extension; keep that mode absent rather than manufacturing a grammar string.
