# Public list storage partition: isolated capability

Two fixed static DATA slots are double buffered by persisted control. Static Spec/WorkflowType are cloned, cleaned and truncated once at an explicitly input-proportional outside-mutation staging boundary. New definition/limit refresh writes nonpublished slot, while Memo continues selecting the previous coherent static/window. Exact pending owner+monotone stamp fences completion; accepted completion swaps static+future window and clears old slot atomically without decoding it. Repeated updates replace pending slot without scanning or deleting a collection. Same-owner refresh reuses published slot only when captured list limit matches. Changed global list limit requires outside-mutation restaging. Root owns actual live getter and ingress wiring.

Dynamic updates expose recent actions/notes without changing pending job stamp, preventing callback activity from repeatedly canceling preview work. Paused stays root-owned. Optional notes are detached in preflight. Source bytes are retained only in static slots; user Notes live separately. Root must reserve MemoVersion before publishing a plan whose memoChanged is true. Pending-only refresh does not consume version; completed window does. No public conflict-token changes are introduced.

Control validates two fixed slot memberships through IsSet, never decoding static DATA. Recent/future cardinality is checked <=5 before loops. Each hot helper reads at most one control DATA (and field metadata), stages at most one static replacement, one old static clear, one notes replacement and one control update. This is a node/cardinality statement, not a universal byte bound: static input/output, user notes and result identifier strings remain explicit byte terms. Memo reads/assembles full required static projection only at export/read. listFirstFuture reads control only.
