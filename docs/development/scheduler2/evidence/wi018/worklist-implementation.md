# Bounded-layout framework implementation plan

Owner: proof_review. Source checkpoint: memo gate committed `6e80c11cf`; DataMap capability `999d0197b`. This is the implementation proposal for the next framework slice, not a claim that DataMap currently bounds transactions. Root reviews the protocol before source changes. Scheduler opt-in remains separate.

## Layout registration and activation

Add `chasm/bounded_layout.go`, registration fields/options in `registrable_component.go`, validation in `registry.go`, and focused `bounded_layout_test.go`/`bounded_work_test.go`. Proposed API is `WithBoundedDataLayout(BoundedDataLayout{Components: []BoundedComponentSlot{...}, MaxImmediateExecutions: ...})`, with generic `BoundedComponent[C](path []string, limits BoundedTaskLimits)` constructing each typed slot. `BoundedTaskLimits` separately bounds persisted pure tasks, persisted side-effect tasks, newly added tasks per transaction, and immediate tasks enqueued per transaction. These are schema invariants, never public queue capacity or a namespace switch. All limits must be explicit and nonnegative; a zero limit forbids that category. Root path must be declared once and match the registered archetype. Component paths and types are fixed, unique and ancestor-complete; root/core visibility and optional fixed maintenance slots count toward the bound. Live and nil libraries install the same descriptor.

The descriptor contains concrete reflect types internally, resolving component IDs after registration. Registration rejects raw Map fields anywhere in this layout, undeclared component-valued fields, interface-typed dynamic component fields, and version-only Memo providers. Memo providers on bounded roots must also implement the accepted nonzero version gate. DATA Field and DataMap children are permitted only under declared fixed components. ParentPtr to a declared ancestor is permitted; deferred Field pointers are rejected on attachment because their pointer/data distinction is runtime state. Unsupported topology fails explicitly: no claimed-bounded root silently falls back to a full walk. Libraries without the option retain every existing path unchanged. DataMap in a default library does not activate this profile.

On NewEmptyTree activation occurs when SetRootComponent identifies its registered root, before structure sync. On NewTreeFromDB activation derives from the persisted root type before hot processing. One cold pass validates all topology: each component at its exact slot/type; direct DATA fields at allowed fixed field paths; DataMap collection at its declared field path and only leaf DATA below it; no component/pointer under DataMap; task limits on every fixed slot. Build a fixed slot array during that pass. Missing optional component slots are nil, not fabricated. Runtime attachment/removal updates a slot pointwise. Fixed-depth paths and collection leaf keys must use the existing encoder; no new truncation or serialization format. Reflection over declared component fields is fixed by the registered Go schema.

The descriptor bounds framework node/task visits. It does not magically bound the bytes in a touched proto or application callback. Report visited node counts plus encoded/decoded bytes separately. Scheduler migration must keep ordinary touched metadata/pages bounded and keep full definition/payload bytes out of unrelated dirty components. It must also supply bounded task validators and handlers. No global payload-size limit is substituted for that obligation.

## Dirty sets and transaction lifecycle

Use insertion-ordered deduplicated sets for (1) structure-dirty component nodes, (2) byte-dirty nodes, and (3) touched nodes whose flags need cleanup. Each set is a slice plus identity membership map. Pending membership suppresses duplicate enqueues only while an entry is waiting. Draining removes pending membership before processing, so a later immediate-task quantum can enqueue the same component again; touched cleanup membership remains transaction-wide. Every actual enqueue/drain is counted. Draining uses an index and includes newly appended work. Do not rebuild any set by scanning the tree. Nodes removed or superseded are skipped only after checking their current parent/slot identity; stale old nodes cannot serialize back into the live tree.

`setValueState` adds a current node to the relevant sets when transitioning to NeedSyncStructure/NeedSerialize. DATA point writes and new collections enqueue only addressed nodes. A component's mutable access still marks that component's bytes/structure as it does today; bounded layout does not infer which Go fields changed. `markSubtreeDirty` marks the addressed node and bounded ancestors, records cleanup membership, and conservatively flags all fixed component slots for task validation. It never descends through DATA collections. This deliberately validates more fixed components than the default lineage optimization, retaining parent/child/ParentPtr invalidation without a dependency graph.

Structure drain processes only dirty components and existing pending DataMap deltas, until both work sources are empty. Split current sync into a one-component implementation and default recursive wrapper. In bounded mode a fixed component sync validates its finite fields, updates fixed children and DataMap handles, and enqueues newly attached components. It does not recurse through collection DATA. Its `childrenToKeep` handling can inspect only declared immediate component/field children, whose count is schema-bounded; DataMap never enters raw-map deleteChildren.

Prevent recursive bulk deletion on ordinary bounded mutations: removing/replacing a fixed component whose owned collections still contain DATA is an invariant error, not implicit cleanup. Checking collection emptiness uses existing Go-map length, not key enumeration. Scheduler cleanup must delete indexed records incrementally while retaining fixed owners; execution deletion is an explicit terminal persistence operation, not permission to sweep records inside a hot CloseTransaction. Leaf DataMap deletes and empty fixed-subtree removal remain bounded. Passive bulk replication application is separately input-proportional and must not adopt this active-mutation rejection blindly.

Serialize the dirty-byte set only. Metadata-only task/principal/link updates continue using the explicit mutation maps; those maps are already proportional to changed entries. Snapshot iteration is untouched. Task generation after serialization can directly add updated metadata as today. Cleanup clears only touched flags, worksets, pending/touched DataMaps and transaction mutation/task metadata maps. It increments the existing epoch on success/error. A failed lease discards the failed tree; no in-place rollback is invented. Reload builds clean derived sets/slots, never inherits aborted work. Replication updates invalidate hydrated owner values as already required and update/rebuild only affected fixed slots; a cold/full snapshot replacement may perform a full input-proportional validation pass. Never call a whole-tree rebuild before each normal transaction.

## Task iteration protocol

Introduce a private iterator specifically for component-task consumers: bounded mode yields the fixed slot array with its actual paths; default mode filters the existing full traversal. Do not alter `andAllChildren` itself. Every task-bearing consumer below must use this explicit iterator, preserving each consumer's existing lifecycle/access/physical-task checks.

For any state/task change, validate all present fixed slots before selecting the earliest pure task and generating side effects. Enforce per-slot persisted task limits after cleanup and new-task insertion; enforce new/immediate transaction limits at AddTask, before an unbounded list can grow. New-task, immediate-enqueue and immediate-execution counters span the whole CloseTransaction and are not reset when executeImmediatePureTasks swaps its pending map. Also cap immediate executions across the whole CloseTransaction: an immediate task that repeatedly enqueues itself must fail an invariant check, never silently truncate or busy-loop. The scheduler's accepted pump is a separate logical-quantum contract and must fit the declared bound. No external RPC moves under the lock.

The slot array is derived cache state; task payload IDs, logical/physical stamps, schedule ordering and access checks stay authoritative. Cold reconstruction validates existing task counts before use. ApplyMutation/ApplySnapshot replacement refreshes the affected slot and task cache; task status refresh/time-skipping re-stamps inspect the same fixed slots. Pending pure task gather remains a snapshot of component identities, so callbacks can delete/replace slots without causing iteration of an orphaned node. Any new component is inserted into its declared slot before immediate-task processing. Task count violations are invariant failures, not buffer drops.

## Tests and measurement gates

1. Equivalent default and bounded fixture: fixed root/child/visibility slots and N=0/4/5/1000/large DATA leaves. Cold reconstruction still visits N; first and second ordinary point mutations have identical fixed node/slot/workset counts independent of N, unrelated DATA decode/encode zero. Compare projected NodesMutation/tasks/stamps after normalizing derived cache state, not only counts.
2. Poison unrelated DATA. Get/Put/Delete one other key, pure-task delivery, metadata update, time-skipping gate/transition, and complete CloseTransaction must not decode poison. Full Snapshot/PartitionedSnapshot must still include its exact bytes and every clean key.
3. Mutable root state invalidates all relevant fixed tasks; DATA child update, ParentPtr ancestor update, closing root and detached child each match default task validity. Include slot deletion/replacement, duplicate/stale physical deliveries, immediate tasks adding/replacing tasks, two immediate quanta re-dirtying the same previously drained component, and earliest timer ties.
4. Inter-flush DataMap delete/reinsert/delete retains accepted tombstone behavior. Failed handler/serializer/close/publication plus durable reload restores exact authoritative state and fresh derived sets. A pre-close abandoned context is still governed by the existing lease-discard boundary; no new rollback promise.
5. Registration/load rejection: missing/duplicate root, conflicting path/type, raw Map, undeclared component, component/pointer under DATA, unexpected metadata kind, excess persisted/new/immediate tasks, infinite immediate self-enqueue. No fallback full scan is permitted on a descriptor claiming bounded layout.
6. Passive child-only and fixed-component replacement through actual ApplyMutation, plus ApplySnapshot and RefreshTasks; verify no lost component slots, pending visibility tasks or physical stamps. Detached NewDetachedExecution with nil handlers/config loads the same descriptor and can fully read/export records without scheduling.
7. Instrument new counters at workset enqueue/drain, fixed-slot visits, path inspections, deletion checks and task-list visits. Existing decode/encode/node-proto byte counters remain. Count bounds are derived from descriptor component count C, declared field count F, maximum path depth D, task limits T, actual touched keys K and addressed payload bytes P. Scheduler quanta must then establish fixed K/P for ordinary mutations; the framework alone does not prove that application bound.

Each step gets focused tests and an independent source review. No scheduler enables the option until all required consumers and failure paths pass.
