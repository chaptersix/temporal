# Bounded queue transactions with one completed-drain descriptor

Status: proposed executable representation and refinement obligations. No runtime changes or claimed implementation proof. This resolves the rectangle-update problem by avoiding rectangle mutation entirely. It preserves the exact queue relation in queue-contract.md, with named maintenance stutters and a finite backlog-dependent delay before another drain. It does not promise backlog-independent admission latency.

## Why automatic-time monotonicity is unavailable

For one immutable definition, spec.GetNextTime caps jitter below the following raw nominal, so automatic actual times increase. Across replacement, occurrence.Update begins after max(current execution time, DisposedThrough), where DisposedThrough is nominal. MutableStateImpl.Now delegates to its time source; the accepted activity property explicitly permits clock rollback. An old nominal100/actual109 can be admitted at109, followed by rollback to101 and replacement, then a new jitter-free nominal102/actual102. A subsequent nominal103/actual110 produces non-prefix expiry at now110/catchup3. Root's `TestBufferClockRollbackAllowsNonPrefixExpiry` records that exact reducer trace and preserves the later waiter. It is a reducer witness, not a new physical-clock experiment. A monotone-time shortcut would weaken the existing contract.

## Representation: two generations, at most one predicate

Use six fixed queue classes: automatic or explicit, each partitioned into ordinary/cancel/terminate. Retain concrete policy and all IDs in records; the classes merely summarize query behavior. Assign global strictly increasing admission sequences. Store keyed records and point-update indexes in generation A. No pending descriptor means A is the entire logical queue.

A successful drain publishes an immutable descriptor D containing: old generation A, its fixed maximum sequence and record count N, paused/limited eligibility at the drain's time, exact catchup threshold, first eligible sequence, selected sequence, and drain disposition counts. D's survivor predicate is exactly the eligible/not-selected/not-superseded relation in queue-contract.md. Ineligible entries after selected are also removed. The descriptor is a representation of a **completed logical drain**, not a pending choice that later configuration can reinterpret.

In the same transaction, issue selected, update operation/queue/count/action/counter/lease metadata exactly once, and create empty generation B. This publication is the linearization point. Request preparation, limits, identity exhaustion and publication failures leave no descriptor or partial removal. The no-eligible drain publishes the all-removed predicate and no operation; operation-unavailable with an eligible candidate publishes nothing.

Thereafter logical queue = surviving unmoved A records plus B records, sorted by original admission sequence. New admissions append directly to B with sequences above A's frozen maximum. Their times may be earlier than any old cutoff: D applies only to A. No global timestamp watermark incorrectly suppresses them. Public counts and effect-class counts are the exact logical counts, not physical A+B cardinality.

Each maintenance quantum handles a fixed K old records (start with K=1). It evaluates D against each addressed record. A survivor is point-inserted into B with its original sequence; every processed record is point-deleted from A. Both changes and counters/cursor are one transaction. Moving a survivor changes physical placement, not logical membership or counts. Removed records were already logically absent and never produce a second disposition. A's remaining physical count decreases regardless of eligibility, updates or new arrivals. When A becomes empty, discard its empty index roots and D; B becomes the sole generation. There is never a third generation or a chain of filters.

While D exists, another drain does not linearize. It is a named maintenance wait; no public API is rejected, blocked awaiting a scan, or silently reordered. Other normal scheduler transitions continue. Maintenance is charged as a fixed mandatory part of each valid coordinator quantum while debt exists, and a fenced physical continuation exists even with no producer ready. Existing maximum-two immediate quanta remains unchanged. Alternatively a fixed maintenance task may supply the same guarantee, but ordinary work must not be able to suppress its ready delivery indefinitely.

## Point-only range index with a concrete bound

For each of six classes, use a Patricia-compressed fixed-width sequence radix trie (uint64, Hs=16 nibble levels). Each sequence node owns a secondary count trie keyed by exact signed seconds/nanoseconds (96 bits, Ht=24 nibble levels). Secondary count tries are also Patricia-compressed; leaves store multiplicity for equal times. Each page has at most F=16 child slots and fixed-width counts. No page serializes all keys. The composite TimeKey's last eight sequence bytes are unnecessary inside the secondary trie; its first twelve bytes supply chronological order.

Compression is a storage requirement, not an optional optimization. Each node records its absolute common-prefix length/key; branch children are indexed by the next nibble, and unary branches are collapsed. Missing-child insertion or prefix mismatch creates at most one branch and one leaf. Point deletion removes the leaf and merges a resulting unary branch without descending its surviving subtree. Prefix-count queries compare compressed prefix bounds before descending; skipped levels do not increase the depth bound.

Splitting a sequence prefix needs the old subtree's complete secondary summary immediately. It must **not** clone all secondary nodes. Use immutable canonical secondary Patricia nodes, shared roots, and path-copy point updates. Canonical encoding includes prefix, sorted child references, multiplicity/count and schema version; equal trees have equal structural identity irrespective of insertion order. Content-addressed IDs require exact bounded-node byte equality on reuse, not unverified hash equality. A new outer branch starts from the old child's secondary root and performs one point addition. Outer branch collapse reuses its surviving child's summary. Canonicalization ensures equal summaries converge rather than accumulating divergent duplicate trees.

Reference accounting for index nodes is separate from payload owners. Batch all root/edge reference deltas in the transaction and verify nonnegative counts before publication. For a point change, canonical old/new secondary trees share every off-path subtree; only boundary paths can become unreachable. During outer collapse, the parent's post-delete summary equals its surviving child's canonical root, which remains referenced. Thus recursive release is bounded by the same changed paths, **provided canonical identity and batched root accounting are enforced**. Implementation must count release visits and prove this lemma; absent that proof use an explicitly budgeted fenced garbage worklist, never an eager unbounded release disguised as Delete. Rollback restores node references and roots together.

Uncompressed 17-by-25 path allocation per entry is unacceptable as the proposed storage shape. Compression gives linear secondary nodes in each outer subtree's distinct timestamp count; a conservative nonsharing total bound is roughly two secondary nodes per record per visited outer ancestor, at most 2*N*(Hs+1), plus O(N) outer nodes and record bodies. Canonical sharing can improve this but is not an assumed savings guarantee. Frozen node encoding/path metadata, count/refcount widths, CHASM per-node overhead and both-generation transient duplication must be measured at N=1000 and above against the actual mutable-state size accounting. Existing 8MiB enforcement remains an actual ingress/storage constraint, not a silently substituted queue-count cap. A fixed theoretical visit bound does not establish that a useful disabled-capacity workload fits that resource budget; this is an explicit pre-acceptance gate.

Insertion/deletion follows the one sequence path and updates the time count along that path in every sequence ancestor. A point mutation touches at most (Hs+1)*(Ht+1)+(Hs+1) pages before any fixed schema overhead. It never walks another record. Parent/child linkage, count underflow/overflow, empty-page removal and rollback are part of that same bounded point update. Outer sequence pages have explicit ownership; immutable canonical secondary pages use the bounded reference-delta protocol above. Neither may hide an unbounded recursive release.

A sequence interval decomposes into at most 2*F*(Hs+1) canonical prefix subtrees. At each subtree, a time interval count traverses at most two boundary paths and their siblings, conservatively 2*F*(Ht+1) slots. Thus a rectangle count has a conservative 4*F^2*(Hs+1)*(Ht+1) slot bound, independent of N. A sequence minimum/maximum under a time predicate descends one sequence path, inspecting at most F children at each level and querying each child's secondary time count. Nonzero counts choose the next branch; no dead-record skipping is needed. An explicit class uses its ordinary sequence extrema/counts without time filtering.

Drain queries first eligible across the six classes, last eligible effect across four classes, expired/ineligible automatic counts, and eligible effect counts before selected. Point membership prevents double-counting the first eligible effect record. All are a fixed number of interval counts/extrema, plus one selected-record read. Computing D and its exact counts therefore has a fixed page/slot bound. D is **not** applied as a rectangle update to these indexes. A's indexes continue describing its physical records until point cleanup removes them.

While D exists, normal handlers use persisted logical total/class counts and addressed records. They do not need another eligibility query to choose a drain, since no new drain can linearize until D is cleared. If an observer needs a full queue snapshot, it enumerates and filters A plus B as explicit output-proportional/offline work; no ordinary scheduler mutation does so. These index constants are substantial; M4 must measure them. Fixed work is not itself a claim of good latency.

## Complete queue-consumer binding during maintenance

- `stateFor`/`publishTransition` and decision cloning: public path must use a bounded queue summary/addressed record adapter. Materializing a slice from A+B is forbidden. Internal finite-profile slice reducer remains the independent relation used by tests.
- `QueueAvailable`, automatic admission, manual/backfill CanDispatch/dispatch, BUFFER_ONE and directAdmission: use logical QueueCount, not physical generation lengths. Keep live MaxBufferSize and BufferedOperations formulas unchanged. New records go to B. An owner waiting for capacity retains its exact OwnerKey and class; relocation cannot revoke it.
- `planWorkFor`/`demands`: do not fabricate a different drain candidate or rotate NextQueue/NextOperation/NextWork on maintenance. The last logical drain already rotated exactly as reference. Mark new drain service deferred by D; keep manual/backfill/automatic readiness and concrete vacancy leases evaluated normally. Maintenance does not count as an admission or consume a vacancy.
- `reconcileEffects`: use logical cancel/terminate class counts across both generations, **without catchup or paused filtering**. Existing source considers every still-queued effect policy, not only drain-eligible entries. Terminate dominates cancel; retain target/accepted/ambiguous semantics. Maintenance cannot resurrect an effect removed at D's publication.
- `publicInfoProjection`, SearchAttributes, backfill batch capacity, public overlap counts: use logical QueueCount; BufferSize remains QueueCount+UnconfirmedStarts, distinct from configured occupancy. Drain's action actual time and missed/superseded counts come from D's already-computed transition result; no rescanning before/after queues.
- idleDeadline and time-skipping queue checks: use logical membership. Physical cleanup debt cannot resurrect accepted work. If closure is otherwise allowed, close fences all authority and lets execution deletion/closed cleanup own remaining DATA. If not closing, a due maintenance task is an internal-work wake and must not be abandoned by clock skipping; virtual-clock/reload tests must show it progresses.
- root updates: change current controls only. Do not re-evaluate D's old disposition. Retained entries use current controls at the next drain, as the reference does. Clock rollback, catchup enlargement and disabling/re-enabling capacity do not restore already removed entries.
- delete/close/recreation: revoke issuance immediately; fence maintenance by incarnation, generation and descriptor token. Old physical deliveries cannot modify B in another incarnation. Detached readers reconstruct exact logical queue without runtime configuration; missing nodes fail closed.

## Refinement, progress and fairness

Projection P filters A by D, unions B, and orders by immutable sequence. Descriptor publication projects to exactly one reference drain. Point cleanup projects to identity (a named stutter). Ordinary API/producer/result transitions operate on P and project to their same reference transitions. Concurrent arrivals cannot be included retroactively in D; controls changing afterward cannot rewrite its decision. There is no speculative scan validation that can restart under adversarial updates. Failed publication restores both physical generations and P.

Let R be remaining physical A records immediately after a successful maintenance commit. With K=1, each such commit reduces R by one until zero. New arrivals only affect B, so they cannot increase R. Under fair delivery and eventual successful persistence, D finishes within N successful maintenance quanta, plus one fixed finalization if not folded into the last deletion. This is a bound parameterized by the finite snapshot at linearization, not an assumption that ingress stops. Each handler's work remains fixed. Constant maintenance plus one selected ordinary quantum prevents cleanup from monopolizing producer service; mandatory maintenance prevents sustained producer arrivals from starving cleanup.

No later drain starts its own epoch before this one finishes. After finite maintenance, the existing cyclic coordinator/lease rules apply; stable definitions and recurring usable capacity remain the stated conditions for eventual service. The accepted backfill-arbitration contract expressly rejects an unconditional finite sixteen-ready-grant guarantee. This protocol adds a named finite implementation wait, not a new external capacity requirement or an infinite idle state. It does not claim the original finite model already proves that wait. A new refinement/liveness model must include R and sustained arrivals, not just successful example traces.

Observable timing can include N/K extra maintenance quanta before the next drain, so no claim of unchanged latency or catchup outcome under identical wall-clock timings is valid. Reference scheduling already permits fair finite delivery delay; correctness is a stuttering trace refinement using each actual linearization time. If a stronger contract requires a backlog-independent count of grants before every ready drain, this algorithm cannot satisfy it. No such stronger guarantee is claimed by the accepted arbitration document; implementation acceptance must explicitly record the finite-delay boundary.

## Required executable gates before adoption

1. Full-state reference traces at every commit, with non-prefix expiry, all policies, root update during cleanup, arrival below prior cutoff, complete/ack before cleanup ends, BUFFER_ONE, live capacity reduction and concrete owner preservation.
2. Adversarial sustained arrivals and updates while R decreases exactly, with a ready next drain eventually served. Independent fair recovery suffix and model fairness assumptions; no claim of infinite liveness from a finite test.
3. Counter bounds for query/point cleanup and CloseTransaction at N=4,5,1000 and larger, identical schema constants, including clean-node visits and secondary trie maintenance. No periodic full-index rebuild.
4. Failed publication at descriptor creation and survivor move; reload every phase; duplicate/stale maintenance envelopes; delete/recreate and virtual-clock skip with debt. Exact public observation equality throughout.
5. Source review of every queue reader above. No old slice hydration, effect scan or public missed-count scan may remain on the public hot path.

This is a feasible algorithmic proposal subject to these gates, not a declaration that current runtime satisfies them.
