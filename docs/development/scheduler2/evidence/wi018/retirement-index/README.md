# Exact StartOnly retirement primitive

This capability preserves `retentionEviction` ordering: signed legacy `Nominal`, then lexicographic operation ID. It does not substitute exact timestamp or admission-sequence order. Within one execution the common incarnation prefix can be removed. The generated suffix maximum is 73 ASCII bytes (`backfill/` + uint64 + `/` + RFC3339Nano + `/action/start`). `NewRetirementKey` rejects empty, overlong, NUL and non-ASCII suffixes; the integration must verify the operation's incarnation and generated identity before removing that prefix.

The key is 88 bytes: sign-biased big-endian nominal8, suffix80 with zero padding. `RetirementIndex` is a separate 16-byte owner identity. `InsertRetirement`, `DeleteRetirement`, and `RetirementMinimum` use the existing `CountBatch` overlay and its single atomic backend publication. Duplicate insertion and missing deletion poison the batch. Query errors also poison the batch. Minimum queries stage nothing. Existing count/sequence encodings are unchanged.

The exclusively owned Patricia tree has sorted buckets of at most16 keys. A branch exists only for count>16. Each collision-free page identity consists of a prefix length and the masked88-byte prefix. Parent/child prefix, direction, strict depth progression, cardinality and bucket order are validated along touched paths; the minimum query also validates the immediate sibling. Full unrelated-subtree auditing is deliberately not a hot operation. No page or root is shared between owner namespaces. Split at17 and collapse at16 yield the same representation independent of insertion order; no subtree enumeration or bulk root drop exists.

## Source-derived bounds

The conservative path limit is704 branch bits (the present valid suffix grammar restricts realizable paths further). A query or point mutation performs at most2 root reads +2 initial-node reads +704*4 child reads = **2820 `CountStats.Reads`**; each `readIndex` counts both overlay and backing lookup when needed. Mutations stage at most3 page keys per branch plus4 terminal/root keys = **2116 distinct changes**, conservatively including collapse deletes. A bucket encoding is at most1410 bytes; a branch189; a root90. A page backend key is154 bytes, root38. Thus total key+value publication bytes are conservatively at most2116*(1410+154)=3,309,424 per point mutation. This intentionally loose fixed-width ceiling is not a measured typical transaction size.

CPU work is also fixed by key width: prefix masking visits at most704 bits; difference/comparison at most88 bytes; bucket decode/validation visits at most16 keys (each suffix at most80 bytes); bucket insertion sorts by bounded binary search and moves at most17 keys. The path bound multiplies these constants, not backlog length. No count-root references, hashes, ownership releases or enumeration are introduced. Actual CHASM framing/serialization, enclosing execution state and runtime consumer behavior require separate adapter/runtime evidence.

## Validation

`final-routine.log` runs the complete queueindex package with `CGO_ENABLED=0 GOMAXPROCS=4 go test -tags test_dep -p 2 ... -count=1 -v`. Tests include Rapid reference traces with whole-store reachability checks; ascending/reversed insertion byte equality; deletion/rekey/collapse equality with rebuilt trees; signed extremes, prefix lexical ties, maximum generated suffix; independent owner isolation; every backing-read failure and failed atomic Apply for ordinary insert/delete/minimum and exact16/17 split/collapse; mixed ready+retirement batch rollback; malformed owning roots, missing referenced children, counters, child prefixes and bucket contents; duplicate/missing poisoning; reload and staged minimum.

A 504-key valid-encoding witness forces a long minimum path (1956 counted reads) and then deletes every key, requiring an empty backing store. This is a fixed-width structural witness, not a claim that every synthetic ASCII suffix is generated by scheduler admission.
