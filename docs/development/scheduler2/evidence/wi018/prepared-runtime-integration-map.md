# Prepared calendar runtime integration map

Status: implementation map from current source after native capability review. No routing or frozen-source edits are authorized by this document itself. Root owns milestone acceptance and shared-file integration. The intended next implementation is the pure whole-spec continuation, followed by persisted definition ownership and actual coordinator/preview wiring; provider capability alone is not WI018 completion.

## Current repeated work and exact callers

- generator.go prepareGeneration/newEnumerator calls occurrence.NewPublic inside the mutation, including full canonicalization/compilation; it also calls Run to validate a one-probe window. coordinator.go currentEnumerator unmarshals the whole Definition.Spec and recompiles on every automatic scan and transfer. backfill.go backfillEnumerator repeats this for selected range scanning. A transfer/disposition does not intrinsically need calendar compilation.
- occurrence/occurrence.go Enumerator.probe invokes NextTimeCandidate; legacy candidate.go does one complete raw union, all necessary exclusions, then a second complete raw union for jitter. Eight probes bound candidates, not term/range/zone work. CalendarNextState and prepared timezone pages already bound one calendar term, but no whole-spec continuation exists.
- public_projection.go publicFuture recompiles and calls GetNextTime up to10 times. publishPublicTransition reads PublicSchedule then public_mutation.go publishPublicList clones/cleans the entire Spec before its top-level slices are truncated. Every completion can therefore repeat definition-proportional work. Truncating top-level term count does not bound nested range bytes.
- public.go Memo clones the stored list partition; Scheduler has no MemoVersion method or bounded-layout opt-in. ContextMetadata also reads PublicSchedule just to obtain two action strings. SearchAttributes currently reads PublicList's first future entry. These paths must be changed with projection storage, not hidden under a new enumerator.
- library.go NewNilLibrary constructs a legacy builder; live NewLibrary adds handlers. public_api_test_dep.go installs the real dynamic getters and shares that builder with the frontend. There is no prepared source service in this wiring yet.
- Backfills remain a root repeated field and selectedBackfill scans it. That separate cardinality gate must be assigned alongside this work; bounded occurrence math cannot close the complete transaction claim while command selection is unbounded.

## Shared source service and outside-mutation preparation

Introduce one live preparation service per shared runtime/provider scope, explicitly injected into Library and frontend/task executors. It owns one platform Environment and long-lived per-builder Resolver caches. Unix selects NewUnixEnvironment; Windows selects NewWindowsEnvironment. Do not build a new Environment per query, spec or library read, and do not initialize an environment from NewNilLibrary. Nil libraries register the persisted types/tasks without performing filesystem/clock/config resolution.

The shared provider's startup boundary and process-immutable TZ/ZONEINFO assumption are explicit. The source audit found no production mutation; this does not recover arbitrary earlier stdlib Local/ZONEINFO history. API-created/reloaded requests use the shared resolver's actual source snapshots, including native Windows type and initialization year. The provider runs before entering a write callback or in a side-effect preparation task. No currentEnumerator replacement may call Resolve, load files, parse TZif or build masks under a hot write lock.

Canonicalization must be separated from timezone resolution. Add a source-derived exported pure canonicalization/validation seam in the legacy scheduler builder (or move the existing pure helpers to shared code), used by both the existing compiler and prepared staging. Do not overwrite TimezoneName with UTC before canonicalization: cron timezone syntax and explicit-name conflicts are semantic inputs. StageCalendarSource is safe for an already canonical single structured calendar because its temporary spec has no external timezone lookup; the whole-spec path must not rely on a second hidden named resolution.

A StagedDefinition owns canonical bytes, original definition identity, immutable mask/interval pages, seed pages, one resolved timezone snapshot and an optional initial static list projection. Necessary incoming request normalization/hash/mask compilation is input-proportional and outside mutation. For cache loss after reload, a dedicated preparation read obtains the one owned source snapshot and reconstructs staging outside mutation; it is a separately measured cold/input preparation boundary. Ordinary work quanta consume only installed fixed pages. This boundary must be observable in counters/logs rather than mislabeled constant-cost work.

Do not approximate the named cache TTL with virtual execution time. common/cache expires on process wall time, whereas ctx.Now is the execution clock. Before starting a new source-evaluation job, a side-effect source check resolves through the shared cache outside mutation and returns the immutable snapshot plus capturedAt. Cache hits are cheap but still outside the callback. The job pins that snapshot through its internal stutters, like one existing compiled call. A replacement returned by a later check fences unfinished work by semantic fingerprint; completed Pending candidates remain authoritative. Definition/owner/token fences reject late preparation responses after update/close. An optimized refresh schedule may be added only after proving the wall-clock/virtual-clock relation; a raw ctx.Now+24h deadline is not that proof.

## Fixed persisted definition layout

Add one DefinitionPreparation child, rather than a component per calendar term. It owns fixed header/control, immutable source DATA, DataMap term pages, DataMap seed pages, one TimezonePreparation child, installed-prefix cursors and FIFO superseded owners. A term page carries at most16 fixed records: canonical CalendarMasks for include/exclude calendars, or fixed interval seconds/phase. Each page is fenced by definition owner/type/ordinal. Calendar term identity derives from canonical definition identity plus class/ordinal, so a reused CalendarNextState cannot cross term boundaries.

The definition header holds term counts, seed byte length, start/end bounds, jitter duration, immutable definition ID and revision. Use checked machine-width/count representations without introducing a new public term/range cap. Keep complete canonical spec, comments, source names, TZif/native input and request template in separately addressed input DATA. A timezone refresh replaces only timezone ownership; it must not reinstall unchanged calendar pages.

Stage complete masks outside mutation using the already verified range compiler, then install at most16 fixed term/seed pages per transaction. This avoids rereading or expanding arbitrary range lists while scanning. Existing CalendarPreparation range-page capability remains valid, but runtime whole-spec storage must not attach an unbounded component collection or concatenate all term states into root control.

Replacement publishes a new owner/header and exact old installed-prefix descriptor atomically. Readers use the installed current owner only; incomplete definitions yield a named preparation stutter. Old pages need no per-backfill reference once revision checks force lazy rebase before evaluation: completed candidates retain nominal/actual authority, and old admitted requests already own their immutable payloads. A stale in-flight context/side-effect response is fenced before any page access or install.

## Pure whole-spec continuation

Implement a value-only PreparedSpecState around the existing occurrence State, with a fixed work cursor:

1. **Nominal union:** original search boundary, term ordinal, minimum accumulator and one CalendarNextState. Advance at most64 elementary units per quantum. A calendar uses its existing <=64-phase budget; an interval consumes one fixed arithmetic unit using Go's original truncating signed division and overflow behavior. Do not substitute mathematical floor division. Visit all calendar/interval terms before accepting the minimum; duplicate minima produce one raw instant.
2. **Nominal bounds:** apply the caller contract. Automatic NewPublic currently clamps its end to UTC2100 even though public timestamps can extend to9999; compiled-calendar primitive bounds are local-year based. Preserve the explicit local2100→UTC2101 witness: raw calendar can produce that instant, while GetNextTime preview rejects it by UTC year. Do not normalize the primitive and wrapper into one broad rule.
3. **Exclusion:** convert nominal to one prepared local civil value and test fixed masks page-by-page. A new bounded matches primitive must mirror compiledCalendar.matches, including AllYears and day/week conjunction. Stop on the first match; an excluded raw candidate retains Actual==Nominal and advances disposition only under the existing Peek/Run protocol.
4. **Following raw union:** for an eligible nominal, run the same unfiltered raw union after nominal to cap jitter. Exclusions do not filter this following instant; start/end/UTC wrapper exhaustion must not be applied prematurely to it. Retain nominal separately while this union yields.
5. **Jitter:** preserve time.Time.MarshalBinary of UTC nominal, exact seed concatenation, farm.Fingerprint32, nonnegative cap, millisecond truncation and MaxUint32 range. Do not prehash seed or use the seed-hash API as a substitute. Seed length is not an established schema constant. Use fixed20-byte seed pages and a source-derived streaming Farm32 continuation (h/g/f, byte offset, total length and fixed suffix data); <=24-byte inputs use the exact short branches. The Go module's Farm32 long branch already advances20bytes per iteration. Differential gate must compare all length boundaries, all quantum partitions, current architecture Fingerprint32 and its pure-Go reference.
6. **Publish Pending:** only after all phases complete, update SearchAfter/EligibleSeen and install one immutable candidate. A preparation/term/hash yield is not a completed raw probe and cannot increment exclusion iteration counters or advance DisposedThrough.

Any addressed read error returns the original input continuation and no candidate/output. A timezone fingerprint change resets only unfinished subwork to its saved original boundary. A definition update uses the existing Update/RebaseRange semantics: automatic boundary=max(update time, disposed nominal), backfill boundary=disposed nominal; admitted operation/request authority is untouched. DisposeRange becomes fixed validation over header/state/pending and must not reconstruct the enumerator.

Use the existing finite Enumerator as the executable reference. Extend Rapid traces with random include/interval/exclude counts, large duplicate ranges, negative/fractional boundary times, DST folds/gaps, impossible sets, end horizons, live source replacement, time rollback, jitter and every partition of the same fixed work budget. Preserve existing Lean/FizzBee scope; a passing primitive does not silently extend the finite proof to the full profile.

## Generator/backfill integration and ownership

Generator receives fixed PreparedDefinition and SpecWork fields/children. configureGeneration accepts a staged definition (precomputed outside mutation), publishes ownership plus a preparation/scan continuation, and removes its synchronous e.Run validation probe. currentEnumerator/backfillEnumerator cease loading Definition.Spec in the new prepared profile. scanAutomatic and scanBackfill call the prepared pure engine through addressed page readers; transferAutomatic and transferBackfill use fixed Dispose validation and the existing request/candidate lease.

Do not change coordinator admission fairness or allow internal preparation to acquire a vacancy/operation permit. Add explicit maintenance demands for definition install, source response merge, preview and old-owner cleanup, with fixed metadata readiness checks. Rotate maintenance classes and cap their share so a continuously replaced definition cannot starve accepted commands or page reclamation. Continue to honor the existing transaction quanta limit; no internal helper may drain arbitrary work merely because the outer task is called once.

Public checkPublicCommandCapacity bounds combined Manuals+Backfills at100 (finite profile4), so fixed100 selection is cardinality-independent; no additional frontier is required. Audit ingress and reconstruction enforce this existing invariant, including BackfillFocus under capacity waits. Lazy revision/fingerprint checks perform fixed resets only for the selected owner.

## Preview and visibility contract

Describe currently promises immediate read-only future output, including after create; public_projection tests assert10 values, remaining-action truncation and no mutations. It also observes live dynamic compute-limit changes. Keep a read-only ephemeral prepared-spec driver for Describe/MatchingTimes over a consistent definition snapshot, with no persisted cursor writes. Required response/spec output and full read evaluation are measured separately from the mutation bound. Do not return an empty/partial response merely because a new hot-work quantum ended. A compute-limit stop retains its existing meaning.

List/visibility is already asynchronous: the shared FutureActionTimesAdvanceWhilePaused contract waits for initial and advancing entries. Maintain a separate durable preview job with output<=10, source revision/fingerprint, original after=max(now,cursor,updateTime), limited/remaining snapshot and compute-limit parameters. Raw-candidate iteration counts match GetNextTime (one count per completed raw probe, not per term/hash step); warning/maximum getters are sampled at the start of each logical GetNextTime output operation, as the old compiled method does. Automatic occurrence probing retains its separate no-hard-preview-limit behavior.

On a new preview stamp, cancel unfinished old-stamp work, retain the last complete published projection as the asynchronous visibility record, and schedule bounded work even while paused. Publish a new future window atomically only when complete or an actual semantic compute-limit/exhaustion result occurs. Never mix a new definition's list Spec with an old definition's future window. A newer definition supersedes the old pending preview rather than finishing and publishing it late. Capacity/paused/remaining changes fence the appropriate job inputs; current exposed pause/recent counters still update atomically through fixed dynamic metadata. Reconcile expiry/advance work so the eventual List projection progresses while paused and cannot be starved by admission backlog.

Split list storage into immutable cleaned definition/action metadata (prepared once at definition ingestion) and fixed dynamic metadata (recent-five, future-five, counters, publication stamp, stored list-limit value). Memo assembles the full required message only on visibility export/read. Root has implemented dedicated persisted MemoVersion; preserve its atomic increments on every exposed change; close compares only that revision through the existing framework capability. SearchAttributes reads the fixed first-future/count fields, not the full spec. ContextMetadata reads a dedicated action-type/task-queue metadata partition. Live list truncation settings are captured into fixed projection control; detached reads never fetch runtime configuration.

The local helper tests that directly call publishPublicList on the legacy profile remain valid. Add prepared-profile tests that explicitly drive bounded preview quanta and test the public immediate-Describe/eventual-List boundaries rather than weakening external assertions. Initial create/update may stage static definition input outside mutation; an immediate Describe must compute a coherent read result even while durable installation/preview is unfinished. No public API must expose a new pending/error status solely for this implementation detail.

## Cleanup and framework close

Maintain one FIFO cleanup head with owner ID, exact installed prefixes and phase/page cursor. Each selected maintenance quantum preflights/deletes at most16 pages from one owner, then advances/removes that descriptor. Term/seed and timezone generations have independent ownership. New replacements append behind existing owners and cannot reset cleanup progress. Do not delete a whole DataMap/component while descendants remain. A completed old Pending needs no old pages; its frozen times/revision and issuance request authority are sufficient.

Idle detection must consider preparation/preview/source-response/cleanup obligations explicitly. Close fences future issuance and preparation responses using fixed tokens. Where the existing close protocol retains closed records until execution deletion, keep those remaining owners retained for that separately admitted deletion boundary; do not add an unbounded close-time walk. Ordinary open-execution cleanup must have a durable scheduled obligation and progress under repeated updates.

Only after all root unbounded collections and hot reads are removed, register the new fixed-field layout plus existing DataMaps with CHASM bounded worklists. Include actual handler+CloseTransaction counters at N4/5/1000/10000 definitions/backlog, with source blob poison tests, per-page byte bounds, task validation/serialization and no unrelated source decode. Count the source service/preparation boundary separately from hot quanta; count full cold reconstruction, Memo export and Describe separately rather than claiming a constant total response cost.
