# Transactional payload ownership integration

This slice supplies keyed immutable BlobRecords and separate BlobReferences counts, plus a fixed PayloadStore version selector. The private fresh-creation path can select it; default public constructors still use the old representation pending review. Existing records are not migrated. Keyed operation runtime remains explicitly gated until projections/dispatcher integration. Operation retirement helper integration and effect guards are separately owned concurrent work.

All owner writers use bounded reference deltas: public definition, generator definition, immutable issuance records and carryover. Request changes carry old/new tuples in operationRecordPlan. Completion-window eviction is preflighted, including self-eviction, and coalesced into the same addressed record plan. A public definition update prepares both generator and public owners together before owner publication. Metadata-only operation updates do not load requests. Keyed storage never executes the legacy collector.

A delta touches at most six owners and 36 reference slots; references are deduplicated within each owner, combined across owners, and sorted over that fixed key set for deterministic publication. Refcounts are checked for missing/zero values, underflow and overflow. Unused prepared content is not published. Net-zero ownership does not delete/reinsert bytes. Content bytes and owner counts publish in the same CHASM transaction as their owning records. Release-only changes never hydrate old blob bytes; materialization/new-byte comparison validates content identity. The root review identified existing positive count plus missing content and newly prepared bytes; this now fails closed instead of discarding the new bytes and accepting an invalid new owner. Forged prepared bytes are rejected too.

Generation and definition publication are split from preparation. Existing post-publication coordinator reconciliation still relies on the enclosing CHASM transaction's discard on error; this slice does not claim independently committed owner writes. No snapshot or RPC is exposed by blob publication. Close retains all owner/content records for existing execution deletion, without scanning/releasing every owner.

Directed checks include fresh keyed creation, public+generator+request sharing across template versions, immutable old issuance, poisoned final-release content (proving no decode), result carryover snapshots/replacement, duplicate terminal delivery, close retention, fixed completion-window self-eviction, and UpdatePublic counter corruption rejecting before root/generator/definition changes. Planner checks cover duplicate refs/owners, owner budget, underflow/overflow, missing/zero counters, missing content with positive counter, forged supplied bytes, unused candidates, detached inputs and rejected publication/reload.
