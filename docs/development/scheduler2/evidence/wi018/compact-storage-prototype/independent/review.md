# Independent mutable packed-store review

Reviewed store.go, mutation.go, reference/fault tests and mutable-store-contract. Three original corruption cases were accepted: a touched child whose maximum crossed its next parent separator; allocating an ID whose backend page already existed; a referenced child ID beyond control.next. Independent01 reproduces all three (FAIL0.262s). Author repaired bounded inherited exclusive-upper checks throughout Get/insert/delete/rebalance, root/touched-child allocation-frontier checks, collision read before allocating, and strict local ordering before save. Independent range/frontier fixtures use legal8-entry child occupancy so unrelated occupancy checks cannot mask findings.

Corrected full package suite including independent tests PASS1.311s. Additional independent test checks12 empty-store delete/reinsert cycles never reuse page IDs, Get detaches returned overlay bytes, and unrelated namespace read failure permanently poisons an overlay containing prior writes and prevents Commit. Existing tests compare reference maps after1600 point transactions plus deletion to empty and inject all reached insertion/deletion reads and atomic Apply rejection. Author owns required lint and final overall freeze.

Atomicity: page/control writes remain in one detached namespace-shared overlay until Commit; failure poisons subsequent reads/Commit. Backend Apply atomicity is a required backend contract, not implemented database rollback. IDs monotonically advance across empty states; control is retained after final deletion. Lost/malformed allocator history cannot be reconstructed from missing pages: integration must supply expected owner/count and not infer an established namespace is fresh from missing control.

Source bounds per point operation: Get including malformed depth guard <=66 reads (control+root+64 child loads); insertion<=130 reads and distinct overlay changes; deletion<=255 reads and conservatively190 page serialization calls, <=128 distinct overlay keys. Each individual persisted page has<=16 entries, transient split17 and sibling combine<=32. Opaque key/value bytes are variable: byte/CPU costs depend on encountered key/value lengths, not just page count. Arbitrarily many Batch operations remain arbitrarily large; Commit sorts accumulated overlay O(changes log changes). Runtime must bound point operations and measure actual CHASM whole transaction/frame bytes. These facts do not establish8MiB fit or Scheduler integration.

Touched validation is deliberately local: exact child minimum/count and applicable upper bound are checked when a path/sibling is touched; unseen descendant corruption is not globally scanned. Recursive mutation depth is capped64; error/overflow/exhaustion prevents publication. No further concrete blocker found after author corrections. No implementation files edited by reviewer; independent_test.go is the only added code.
