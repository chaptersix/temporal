# Independent compact index review

Reviewed final count/sequence/backend sources, encoding tests, reference/refcount invariants, publication rollback, every-read failure injection, canonical split/merge and inline singleton collapse tests. All12 source hashes in final-manifest.json matched before independent execution. No blocking finding was identified in this standalone index/CHASM adapter capability scope.

Count bucket identities hash the complete canonical node bytes; reference counts remain outside identity and are encoded as canonical unsigned integers. Decoding rejects zero references/counts, nonminimal/overflow integers, duplicate/unsorted keys, aggregate overflow and trailing bytes. The16-key bucket bounds local inspection. Larger branches retain exact multiplicity/distinct counts and fixed child identities. Touched-edge validation enforces increasing split bits and child range/count relations. This is not a full audit of every untouched stored subtree.

Inline outer leaves own only their exact time value. Splitting such a leaf creates a new branch-owned count summary; splitting a branch first acquires a separate owner before updating it. Unary collapse onto a branch releases only a matching duplicate summary with another retained owner. Collapse onto a leaf verifies the exact singleton summary, then removes that one branch owner through the ordinary point update. Tests cover equal/distinct times and either removed side while an independent singleton owner survives. Count temporary cleanup scans only pages created by the point update; retaining the replacement before releasing the predecessor preserves shared untouched pages. No arbitrary whole-root release was added.

Count, outer pages and owning-root changes use one staged batch and one backend Apply. Errors poison the batch. The adapter stages into one CHASM context; actual durable publication remains the enclosing transaction, and framework panics require lease discard. Existing backend and adapter tests distinguish staged commit from persisted publication/reload.

Queue records, concurrent old/new generations, operations, payload owners, whole-record wrappers, DB overhead and heap remain outside this index-only total. No public-capacity reduction or resource-limit increase is justified by this checkpoint. Full scheduler queue equivalence, integration failure/fairness gates and M3/M4 remain open.
