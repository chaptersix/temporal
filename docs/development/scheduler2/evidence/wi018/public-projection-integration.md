# Bounded public action and running projections

Concrete implementation contract after the blob/retirement checkpoint. Default public semantics and capacity remain unchanged. No production routing or existing-record migration. The completed addressed profile never falls back to scanning legacy Actions or Operations; nil projection selector alone selects the retained legacy reference.

## Exact reference behavior

`public_projection.go` appends one PublicAction at admission, before RPC acknowledgment. Actions remain in admission order through filtering. A matching acknowledgment requires the addressed retained operation, matching nonempty chain, nonempty PublicRunID, and an action with empty RunID; only then does it set RunID and ActualTime from Event.StartObservedAt. A duplicate acknowledgment cannot replace either field. Status changes from unspecified to running only; callback-before-ack therefore keeps its completed status when later enriched. Do not add a StartObserved boolean condition absent from the reference.

Recent results are acknowledged actions sorted stably by ActualTime ascending. Stable ties use original action admission order, not acknowledgment arrival, close time, operation ID, nominal time, or run ID. Describe returns the greatest ten in that order; List returns the greatest five. All retained action metadata preserves original admission order, so a monotonic action sequence exactly represents the tie rule. Acknowledged actions outside the top ten cannot reenter without a new first acknowledgment: timestamps never change, and the current top ten persist even after operation retirement. Thus a fixed ten-element window is sufficient; no index over all acknowledged actions is needed.

RunningWorkflows traverses Actions in admission order and includes only records whose operation phase is Started AND acknowledged RunID is nonempty. Running order is therefore admission sequence, independent of acknowledgment/actual-time ordering. ALLOW_ALL acknowledged StartOnly operations are not running by this reference predicate. Callback-only acceptance increments existing Started/action-count semantics but contributes no RunningWorkflows member until acknowledged, and a completed operation never becomes running on later acknowledgment.

CompletedOperations retains the existing stable close-time ordered ten entries, with arrival order breaking equal close times. Keep its existing bounded helper and self-eviction behavior. Completed-window occupancy contributes to configured capacity even if a result is outside recent ten. No capacity cap is derived from projection windows; nonpositive MaxBuffer remains unlimited.

## Schema and ownership

RootState.ProjectionStore -> ProjectionStoreControl{format_version=1,next_action_sequence uint64,running_count int64}. Initialize next sequence to1; reject exhaustion before admission publication. Preserve the selector/control through root replacement. No new reducer State fields are needed.

PublicRuntime retains scalar missed/overlap counters and CompletedOperations (maximum10), but selected profile requires legacy Actions empty. Add `recent_actions` with at most10 `RecentPublicAction{sequence uint64, action PublicAction}` values. Keeping the complete result in this fixed window makes List/recent reads bounded and nonrejecting after preflight; callbacks update both the addressed action record and its window copy when present. Repeated result bytes are bounded ten metadata results, not workflow input/output payloads.

Scheduler.ActionRecords DataMap[operationID] -> PublicActionRecord{sequence uint64,action PublicAction,operation_owned bool}. An action is retained exactly while its operation metadata exists OR its ID is in recent ten. The recent ownership bit is derived by inspecting the fixed window; do not add a third unbounded owner map. An operation-owned action remains available for late callback/ack enrichment even outside recent ten. After operation retirement, retain the action only if recent ten still owns it. Removing the last owner deletes just that DATA record. Action records hold no BlobReferences owner.

Scheduler.RunningRecords DataMap[16-hex action sequence] -> RunningPublicAction{sequence,operation_id,execution WorkflowExecution}. SequenceIndex with disjoint fixed owner ID stores running membership keyed by admission sequence and constant CountKey{} time. Use a separate Scheduler.ProjectionPages DATA collection for running index pages. CountBatch canonical count pages/refcounts can overlap across distinct SequenceIndex owner IDs, so readiness/running plans captured independently on one backend would not be disjoint. Separate collections isolate those refcounts. The running record lets Describe read only returned output metadata, without loading unrelated operations or issuance payloads. Action sequence is stored in ActionRecords, so the operation metadata builder need not preserve another sidecar field beside readiness's ReadySequence.

For selected profile validation reject unknown version, next sequence0, negative RunningCount, nonempty legacy Actions, recent/completion windows longer than10, duplicate recent IDs/sequences, malformed timestamps/empty acknowledged RunID, unsorted recent key order, and invalid fixed control. Validate the running index count against RunningCount at preparation/read boundaries using a bounded total-count query, detecting missing ownership roots. No full record recount occurs on mutation. Legacy records retain their old interpretation; there is no automatic mixed-layout repair.

## Runtime plan seam

`preparePublicTransition(ctx,before,next,event,admitted) (publicTransitionPlan,error)` selects legacy or indexed path. Selected path validates before cloning bounded runtime state, computes disposition counters, prepares at most one addressed new/updated action, assigns an admission sequence only for actual new admission, computes bounded recent and completion windows, and exposes the completed eviction. Existing ScheduleTime source selection (including indexed drain Candidate.ActualTime) remains identical.

`prepareOperationRecords` already coalesces StartOnly and completed-window victims, including self-eviction. After that plan succeeds, call `prepareActionOwnership(ctx,publicPlan,recordPlan) (publicTransitionPlan,error)` to finalize action ownership and running changes against the actual final operation mutations. This avoids a circular dependency: completion eviction is known first; action pruning follows the final record plan. Errors precede blob/index/queue publication. Root dispatcher may extend the same record plan with readiness changes, but projection preparation never claims dispatch authority.

The plan holds detached changed ActionRecords/RunningRecords, fixed successor control/runtime/window values and capture-only index changes. It includes at most four distinct action records: addressed event/new admission, one recent-window victim, and at most two operation-retention victims. Coalesce overlapping IDs before reads/writes. Compare addressed action's old/new phase and acknowledged RunID to update RunningCount and membership; duplicate/stale evidence has no repeated delta. At most three operation changes can affect running membership under the general record-plan envelope, although valid retirement victims are terminal and ordinary transitions affect one.

An absent ActionRecord for a retained addressed public operation is an invariant error; do not reconstruct it from a newer template. A stale event whose operation is absent produces no action update, even if a recent-only ActionRecord survives. A wrong-chain event cannot enrich or alter status. Once an operation is evicted, later evidence remains ignored exactly as current stateFor/Step/HandleNexusCompletion behavior.

`publishPublicTransition(ctx,plan)` writes only prepared records, fixed control/runtime and existing list projection. It performs no action discovery, sort over backlog, or operation-map scan. Readiness/retirement captures use OperationPages; running uses separate ProjectionPages. These independent captures have disjoint collection paths, preventing canonical count-refcount updates from overwriting each other; root applies all captured changes with the same transaction.

## Index and read API dependency

Existing SequenceExtreme filters by time but has no sequence lower bound. Add reviewed read-only `CountBatch.SequenceAtOrAfter(index,lower uint64) (SequenceEntry,bool,error)`, selecting minimum sequence >= lower. Use compressed-trie prefix comparisons and at most one descent plus a remembered right candidate, with validated child progression and fixed64-bit height. It must not delete entries into a temporary batch merely to enumerate. Poison every touched read, test empty/singleton, gaps, uint64 extremes and reference lower-bound results; preserve shared-owner and poisoned-batch behavior. No count/time index semantic changes are needed.

`runningProjection(ctx) ([]*WorkflowExecution,error)` validates root count once, then traverses SequenceAtOrAfter from1. Read one RunningRecords value per returned member, validate its key/sequence and required IDs, and append detached execution metadata. Advance with checked sequence+1; MaxUint64 is terminal, never wrap. Require final output count equal RunningCount and error on missing record. This is explicitly output-proportional Describe work, under one coherent CHASM read snapshot. No silent pagination, count cap, or pending/completed record scan is allowed.

`publicRecent(ctx,count)` for indexed profile clones the bounded window tail, preserving chronological/admission order. `publicInfoProjection` should return an error so DescribePublic propagates missing/corrupt running data honestly; Describe already has an error boundary. It reads exactly recent<=10 plus running output, the current public definition/action payload and fixed info. `publicListProjection` uses the cached recent tail only. SearchAttributes reads validated RunningCount instead of Actions/Operations; its no-error callback follows the existing DATA invariant propagation convention, not a fabricated count. Memo remains the compact persisted list projection. Existing publicFuture/list-spec compilation is the separate calendar gate and must not be misrepresented as solved by this slice.

## Bounded work and required witnesses

Window normalization inspects/sorts at most11 recent entries and11 completion entries. Per transition read/write at most four addressed action records, at most three running membership edits/records, two fixed summary values, and each index's fixed-width path bound. Ordinary List/visibility/recent projection work does not depend on active-operation cardinality. Public result metadata carries accepted workflow/run strings; charge these addressed value bytes explicitly rather than claiming every record is constant-byte independent of user input.

Compare complete public projections to the retained legacy oracle on acknowledgment permutations, actual-time ties, out-of-order actual times, duplicate/wrong-chain results, callback-before-ack and later enrichment, StartOnly retirement, completion self-eviction, late evidence after eviction, and recent-window eviction while the old action is still running. Include at least eleven active/acknowledged actions so fixtures cannot pass with bounded-only data. Verify exact RunningWorkflows admission order, recent10/List5 order, running visibility count, ActionCount/BufferSize and completion occupancy under MaxBuffer<=0 and reductions.

For failures poison unrelated action/operation/request records during an addressed callback; poison a returned running record and require Describe error; corrupt index count/root/window format and reject before writes. After every rejected publication/reload compare prior image and exact count/window/ownership state. Exercise old operation eviction while its recent result remains, then recent eviction deleting its last action owner; confirm no blob ownership change. Measure full handler/CloseTransaction at N4/5/1000 once the complete scheduler layout is enabled; cold reconstruction/export and full Describe remain separately input/output proportional. No fallback scan is permitted as an acceptance shortcut.
