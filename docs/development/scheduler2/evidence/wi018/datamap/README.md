# DataMap capability checkpoint

Additive DATA-only point collection implementation. This is not the bounded-layout worklist or scheduler migration, and does not close WI-018 or M3.

`DataMap[D]` stores a handle; `NewDataMap`, `Get`, `Put`, and `Delete` are its API. Get and Put clone protobuf values, including unknown fields. Missing Get is distinct from malformed/wrong-kind DATA. Hydration binds the owning component and field without enumerating entries. Same-key changes coalesce; synchronization applies addressed deltas. Transaction-local removed-node retention preserves persisted identity across multiple immediate-task structure synchronizations, so delete/reinsert/delete cannot emit contradictory update/delete paths or lose a required tombstone. Missing deletion and canceled new insertion publish no node changes or parent stamp changes. Empty collection metadata may remain. Collection replacement and sharing across fields are rejected.

Context captures the tree epoch, preserved by ContextWithValue. CloseTransaction cleanup increments it on success or failure, rejecting escaped completed contexts. Handles validate tree and owner-value identity; child-only replication invalidates hydrated owner values. Fresh contexts can use cached current handles. Application failure before CloseTransaction relies on existing execution-lease discard and durable reload: the old abandoned tree/context is not dynamically revoked by a new engine hook. No in-place rollback claim is made. Returned and supplied values are detached even across failures. No DataMap mutation is permitted outside an execution lease.

Default Map behavior and complete tree traversal remain. Pending/touched DataMap state is proportional to addressed changes; constructor input staging is explicit input work. Dirty marking, sync recursion, serialization/task traversal and cleanup still walk the default tree. DataMap alone establishes neither a fixed hot-transaction bound nor bounded cold I/O. A fixed layout descriptor, task budgets/worklists and scheduler migration remain required.

Parent owns consolidation after its concurrent preparation changes. Source hash manifest identifies this checkpoint exactly.

Directed checks: N=0/4/5/1000 cold reconstruction has zero DataMap key hydration and unrelated DATA decoding; point Get decodes one addressed payload; unread poisoned blob survives unrelated Get/Put/Delete. Aliases/empty/unknown/nil, stale epoch/cross-root, sharing/replaced owner, actual child-only ApplyMutation, one-overlay and inter-flush permutations are exercised. Replayed NodesMutation is applied to prior committed records. Missing-delete/canceled-put/read mutations and root proto are compared exactly. NewDetachedExecution reads the retained full record with no handlers/config and returns detached values. Rejected publication is modeled by not applying the successful mutation then reloading committed bytes; serializer rejection uses invalid UTF-8, returns no mutation, expires context and preserves the committed reload. These are in-process framework witnesses, not SQL failure injection or a general lease-revocation proof.

Preserved preliminary failures are test/setup and lint-development evidence. Independent review found an inter-flush tombstone defect beyond the initial single-overlay tests; the final source and repeated-sync regression resolve it. Review remains independent of this author record.
