# Prepared and packed runtime refinement addendum

Read-only source mapping for the current local implementation. This supplements, rather than overwrites, [current-mappings.md](../../design/current-mappings.md), whose stated WI010/WI011 source and queue4 abstraction predate these mechanisms. It is **not an executable refinement result or an extension of the accepted Lean theorem**. Relevant acceptance gaps remain in [current-acceptance-audit.md](current-acceptance-audit.md). Source can continue changing; a final executable witness must freeze its own hashes.

## Observable projection

Define a verification-only full-state projection after each successful CHASM commit. Its traversal may be input-proportional and must run outside measured production quanta. Do not confuse the event-local `stateFor` view (only the addressed operation) with this complete projection.

| Abstract observation / obligation | Concrete representation and projection rule |
| --- | --- |
| Execution authority | Exact namespace/business/run incarnation, Closed, configuration revision, policy, paused/limited/remaining, accounting and activity. Preserve IDs verbatim. Old task refs cannot be redirected to a replacement run. |
| Accepted producers and concrete lease | Manual/backfill identities and range bounds; queue-vacancy owner class/key and operation scheduling cursor. Ignore storage addresses but retain which accepted candidate owns a lease. A maintenance step cannot acquire that lease or count as admission. |
| Logical queue | Reconstruct current six-class membership plus retained source-generation records selected by CompletedDrain's frozen predicate; exclude logically removed records still awaiting physical reclamation. Order by sequence. Compare full candidate identity/policy/time and exact retained/ineligible/superseded counts, not merely queue length. |
| Operations and immutable requests | O records resolved through I locator mapping, keyed by public operation ID; phases, chain, nominal/deadline/retry/ready sequence and immutable assembled request bytes. A locator is representation, never a new request identity. Check I O-bit iff corresponding live O; retain required A-only ownership after operation retention. |
| Public action and running membership | Resolve A records with operation-owned identity expansion; include latest/running/canonical completion windows with exact order and membership. R/U sequence locators must resolve to the same I/O identity. E refs and Q issuance bytes are separate: request release removes their obligation without requiring Q decoding. |
| Payload ownership | Resolve action/result/failure refs to bytes for expected output; additionally audit each fixed owner set/refcount independently. Equal counters alone do not prove the right bytes or owner. Carryover semantics remain separate from visibility diagnostics retention. |
| Completed occurrence and disposal | Automatic/backfill continuation revision, SearchAfter, DisposedThrough, Pending identity/nominal/actual, terminal classification. Completed Pending remains authoritative through source refresh; no internal page/term step advances disposal or emits an admission. |
| Source/evaluation jobs | Verification identifier: kind + definition owner/revision + original search boundary (plus backfill ID or preview stamp). Include outstanding source token/recipient and its resolved semantic fingerprint, partial Work ownership and whether its grant is available/consumed. Initial staged installation begins the first automatic lookup explicitly; generic source preparation with no recipient does not grant arbitrary jobs. |
| Preview/public visibility | Published static owner/stamp/target, complete future window, current bounded recent/notes/pause; separately pending owner/stamp/originalAfter/target/limited snapshot and unfinished output/work. One source grant belongs to the whole immutable preview window; per-output computation-policy sampling remains separate. Publish no prefix. Initial visibility readiness is false until a coherent published window; eventual export is a separate observation. |
| Dispatch/recovery authority | Exact claim operation ID, ready sequence, logical wake, expiry and dispatch token; outstanding legal RPC/recovery obligations. Do not erase a claim as storage-only stutter: it authorizes a bounded external attempt and changes which negative result may mutate. Positive evidence retains its separate operation/chain merge rules. |

## Concrete step mapping

| Concrete step | Abstract interpretation | Required invariant / observation point |
| --- | --- | --- |
| Stage source outside mutation | Input preparation; no committed scheduler state change | Bind canonical input, seed, revision and exact resolved source identity. Rejected ingress cannot create accepted intent. Input-proportional work is charged separately. |
| Install at most16 definition/timezone pages | Named `PrepareSource` stutter in business state; progress of a source obligation | Owner/token frontier is monotone and fenced. No candidate/admission/queue budget changes. On final batch, grants and scheduling preflight precede publication. Cache miss/full export is a named read boundary, not a hidden bounded step. |
| Source resolution acknowledgment/grant | `ResolveJobSource` obligation step; business-state stutter | Only the captured recipient receives permission; competing jobs retain their own obligations. Wall-time provider cache semantics are not approximated by execution-time+TTL. Wrong owner/token/preview stamp grants nothing. |
| Partial calendar/raw-union/exclusion/following/jitter quantum | `PrepareCandidate` stutter until a complete result | Fixed work budget; no incomplete minimum/prefix output. Preserve original after and source fingerprint. Changed fingerprint resets the unfinished aggregate, not completed Pending. Year-mask jump is equivalent to omitted nonmatching-year stutters, with unchanged candidate result and raw-probe accounting. |
| Completed raw search / Pending publication | Existing enumerator Peek/result relation | Compare against independent reference output/terminal/compute-limit semantics. Preserve nominal versus actual distinctions and strict boundaries. Automatic/backfill grants end at the corresponding complete lookup, not every partial quantum. |
| Candidate transfer | Existing admission/queue/disposition transition | One admission at most; freeze request identity/bytes; dispose the corresponding nominal only after all rejecting work succeeds. Completed-candidate transfer remains possible while another source check is pending. |
| Fifth-class prepared maintenance | Named maintenance scheduling/stutter, or preview publication below | `NextWork` rotates five classes only for prepared profile. `NextQueue` and `NextOperation` stay four-class; legacy automatic→drain rotation is unchanged. Definition cleanup, timezone cleanup and preview internally rotate three ways. Maintenance cannot take vacancy or operation authority. |
| Completed preview publication | Allowed asynchronous public-projection update, **not** invisible stutter | Publish one coherent static/window pair for captured owner/stamp; newer notes/pause/recent remain immediate. Physical time passing must not restart an unfinished window forever. Refresh is a new job after completed publication; expired captured results may be transiently visible under documented eventual semantics. |
| Stale source/task/preview response | No-op (with incidental framework bookkeeping excluded) | No current grant, admission, budget or external request changes. Stale physical envelopes may be consumed; task IDs are not logical authority. |
| Packed page split/merge/template delta and locator changes | Representation step within an atomic logical transition | Stable identity mapping and O/A ownership; no alias/reuse for live owners; exact expanded records. One editor combines operation/retirement/readiness/projection. Queue uses separate disjoint K/B namespaces and does not allocate locators. Commit/discard supplies whole-transition atomicity across both captures. |
| Incremental old-generation/source cleanup | `ReclaimDetached` stutter | Reclaim only detached unreachable owners; logical queue, published candidates/window, accepted requests and concrete lease unchanged. New arrivals do not extend frozen cleanup debt or authorize reclaim of active generation. |
| Claim / RPC / recovery / result | Existing abstract prepare-attempt, external acceptance/outcome, retry/ambiguity and keyed evidence relations with explicit dispatcher refinement | Persist claim before output; no RPC on rejected claim publication. Recovery uses exact token/wake/expiry and original request identity. Late negative results require live claim; positive chain evidence may settle without reopening authority. |
| Failed publication / cold reload | No abstract commit / reconstruct identical committed projection | Discard staged state and reload fresh objects; compare semantic state plus outstanding obligations. Do not compare only public counters or retain old pointers. Distinguish simulated discard from actual SQLite fault/reload. |

## Existing evidence and exact limits

- `TestIndexedQueueDrainMatchesFinite`, `TestIndexedQueueDrainGeneratedReference`, and `TestQueueStateIndexedPlanReferenceTraces` compare decision/facade selection and aggregate semantics. Queueindex and packedstore tests independently check data structures, sharing, faults and reference operations. They do not compose every public command, source job and dispatcher into one checked trace.
- Prepared spec/calendar/enumerator differential tests, fixed Work codecs, source-task/grant tests and year-mask review establish bounded-stage behavior against their stated reference domains. Existing reference calls may share pinned timezone primitives; trusted dependencies remain explicit.
- Packed physical lifecycle tests and `packed-runtime-independent` exercise selected constructor, callback-before-ack, retries/recovery, corrupt Q cleanup, editor rejection and queue/admission publication. These are valuable concrete witnesses, not an independent abstract commit-by-commit oracle for all representation products.
- Historical Lean4.24.0 enumeration/batching proofs and executable correspondence retain their finite eligibility/jitter assumptions. They do not prove arbitrary-size term sources, timezone parsing, packed records/indexes, source-provider TTL, fifth-class fairness, visibility readiness or SQLite dispatch. No new theorem covering those layers is claimed.
- A current complete projection adapter, trace mapping for the named new stutters, seeded command/fault correspondence over that projection, and mutation witnesses specifically detecting lost grants/packed owners were **not found** in the inspected current evidence. Old saved finite traces do not fill these gaps by themselves.

## Smallest meaningful executable closure work

Use three bounded, composable witness profiles rather than claiming an infeasible exhaustive product. Reuse the existing real-tree harness and independent reference relations; add a verification-only full projection. Store seed, event order, limits, source hashes, dispositions and minimized failing traces. Successful runs establish only these explicit domains.

1. **Prepared lookup/preview refinement.** Small oracle calendars with UTC plus pinned DST/custom-zone cases; include a257-term input to force partial work and a multi-batch source to force installation. Generate budget partitions, reload/discard at commit boundaries, definition updates, source fingerprint changes, clock advance/rollback, pause and competing automatic/backfill/preview jobs. After every commit compare business projection and expected job obligations; after a complete job compare full candidate/window and compute-limit disposition to one reference compiled invocation. Fair suffix drains finite source/preview work while time continues advancing. Required mutations: advance cursor during partial union; grant a stale preview stamp; reset unfinished window whenever its first output expires; clear a grant after every partial; drop first staged lookup grant. The last mutation is a progress/cost witness, not necessarily a safety counterexample.

2. **Packed representation/atomicity correspondence.** Drive the same bounded public command/result trace against addressed reference storage and packed storage, comparing decoded projection after each commit. Include capacity2/5/disabled, queue drain with intervening buffers/replacement/expiry, callback-before-ack, late positive evidence, terminal self-eviction, A-only retention, request/carryover refs and claim/recovery. Inject legal prepublication discard and fresh-object reload. Required mutations: release I while A remains; reuse a live locator; omit E/Q deletion; overlap queue/admission physical namespace; publish operation control without its packed batch; accept a stale negative claim result. Compare immutable request bytes, ownership and obligations, not only counts. This is representation correspondence, not a Lean proof of the reducer.

3. **Coordinator/physical authority composition.** Keep all five prepared work classes eligible alongside all three maintenance kinds, force bounded yields and source round trips, and verify concrete queue owner is stable until transfer. Demonstrate finite progress under a stated fair delivery suffix with legal clock steps and no helper draining unbounded work. Replay legacy saved four-class traces unchanged. Add selected actual SQLite StartDispatch/Recovery/source/visibility envelopes at acceptance/lost-response/close/reload boundaries from the acceptance audit. Required mutations: maintenance consumes vacancy; automatic successor remains four-class and starves maintenance; source response grants a replaced owner; claim is output before commit; initial unready visibility task is acknowledged and dropped.

Do not require every mutation to violate the same oracle: safety, byte ownership, fairness/progress and fixed work counts are distinct observations. For each mutation record the exact expected detector and retain restored-source replay. Finish by rerunning existing pinned proof/correspondence/spec/default/race/lint gates on final source and updating the authoritative mapping/inventory. A passing bounded executable profile closes its stated implementation correspondence gap; any unmodeled product/domain remains explicitly visible to the integrator evaluating M3.
