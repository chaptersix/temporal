# Persisted queue facade and full queue storage evidence

The facade uses QueueState, QueueRecords and QueuePages on Scheduler. QueueState presence exclusively selects indexed storage; mixed legacy Queue slices, unknown format, invalid identities/counts and malformed completed-drain descriptors fail. The finite profile remains available when QueueState is absent. This checkpoint implements six policy/origin partitions, bounded index planning, one-record append, completed-drain publication and one-record physical maintenance. Root owns actual public consumer activation and its separate physical/end-to-end tests.

## Exact disposition and publication

Planning queries each enabled class's eligible count/first, each eligible effect class's last and each effect predecessor count. It reads at most one selected record. The per-class removed set is all ineligible, selected, eligible earlier effects and the first ordinary predecessor, without double counting. Exact signed seconds/nanos thresholds avoid subtraction overflow. A completed descriptor freezes this predicate and its already applied removed/missed/superseded totals. New arrivals append to the next generation; maintenance cannot reinterpret an old predicate after root updates.

Logical summary/version changes and records/index changes share the enclosing CHASM transaction. Append preflights identity/collision/counts before batch publication. Drain verifies the complete value fence, all six physical source counts, all six next-generation absences and source cursor before changing the descriptor. Maintenance stages at most one survivor insertion and one source deletion, validates remaining/cursor, commits the index batch, then removes a logically dead record and advances the fixed descriptor. Framework panics retain the existing failed-lease discard contract.

Prospective append planning for prepublication work-token validation uses a transient CountBatch overlay plus Abort. Its summary must equal persisted summary plus exactly one append/version. The prospective selected record comes from the supplied detached value; no phantom record is published. Prospective completed drains report maintenance-deferred. A prospective plan cannot be published against a different persisted summary.

Planning uses at most20 fixed index queries (6counts,6first extrema,4effect extrema,4effect prefix counts). Drain staging adds at most18queries (6sourcecounts,6new-generationcounts,6source extrema). Maintenance uses one addressed source lookup, at most one insert and one delete, plus6source extrema. Their index depths/bucket bounds are recorded in inline-leaf/review.md. Addressed queued-record bytes remain a separate input term. These formulas do not certify the full Scheduler transaction: other raw collections, default framework traversal and other scheduler paths remain separate WI018 work.

queueProjection is explicit full-physical-state inspection for tests/offline use. It scans cleanup debt even if logical output is empty; it is never a hot handler or required Describe implementation and is not claimed to have cost bounded by logical output alone.

It measures node protobuf bytes, encoded path bytes, page/record counts, and proto.Size of WorkflowMutableState containing the full ChasmNodes map (including map framing). Other execution-info/state fields, database rows and Go heap are excluded. No operation/request payloads are present; the generic harness's unrelated1MiB diagnostic blob is removed.
