# Independent WI-018 framework design review

Reviewer: api_seam. Reviewed draft bounded-public-work.md/WI-018 against actual chasm/map.go, tree.go dirty propagation, map hydration, synchronization/serialization/task traversal and lifecycle paths, plus decision/buffer.go selection/disposal. This is design feedback, not implementation acceptance or measured bounds.

The proposed additive DATA-only keyed collection is a coherent direction. The existing raw Map is a Go map; component hydration enumerates collection children, root mutation marks descendants dirty, serialization and EachPureTask walk descendants. Merely changing scheduler slices to Maps cannot close D59. The draft correctly includes framework worklists and bounded scheduler layout, preserves default libraries, and separates whole-record cold topology reconstruction and mandatory Describe output from hot mutation work. WI-015 acceptance remains dependent; the violation is not deferred to a load report.

## Concrete contracts to settle before the corresponding implementation

1. **Dispatcher ownership and fair issuance.** A fixed set of dispatcher tasks must not repeatedly select the oldest operation while its slow RPC is outstanding. Define durable claim/rotation state, its recovery deadline and commit ordering, or another explicit fair selection protocol. Claiming cannot delete retry authority; an ambiguous accepted start must retain the original request/fence. Crash after claim but before RPC must recover; callback before claim release must win; stale release must not reclaim a newer claim. Existing per-operation task independence cannot be replaced with an in-memory busy set that disappears on reload. This is a missing protocol detail, not a request to weaken the fixed task-count goal.

2. **Closed execution cleanup ownership.** `closeTransactionHandleRootLifecycleChange` changes the backend execution to COMPLETED. Do not assume a scheduler maintenance task remains executable after that transition. Choose existing execution deletion for closed-root DATA, or specify and prove an allowed fenced cleanup mechanism. While running, detached prefix cleanup needs durable bounded ownership and fair scheduling; constant-size root metadata must not accumulate an unbounded list of detached subtree roots. A bounded cleanup batch cannot be the only bound if the cursor/root queue itself grows indefinitely. Reference-count ownership must remain valid until that cleanup disposes each owner.

3. **Lazy handle/transaction lifetime and alias rules.** Freeze the API contract before general framework edits: read-only Get must not manufacture nodes or mark a whole collection dirty; Put/Delete journaling must handle replacement/deletion/reinsert of the same key deterministically. Handles or values escaping a failed transaction must not mutate the next transaction. Replication child-only replacement must invalidate cached parent handles and valueToNode registrations without enumerating the new collection on each access. Raw-map defaults and mixed raw/new collections need independent tests. Missing persisted key versus corrupt/missing referenced node must remain distinguishable; never turn corruption into an empty collection.

4. **Task-bearing worklist completeness.** Component invalidation is not the same as byte serialization. Root changes can invalidate descendant tasks even if their DATA was untouched; pointer/parent-dependent validation and newly attached/deleted components must be included. The bounded-layout optimization needs an explicit opt-in/eligibility rule and fallback, rather than a global assumption that all library components have fixed count. Test pure-task addition/removal within a transaction, time skipping, visibility/lifecycle, duplicate physical delivery and replication replacement. Count all preparatory and cleanup walks, not only `closeTransactionSerializeNodes`.

5. **Freeze reference equivalence before indexing.** Current DrainIndex chooses the first eligible waiter unless a later eligible cancel/terminate waiter replaces it; drain removes only the first eligible predecessor and earlier eligible effect-policy entries, while retaining ordinary intervening waiters. The draft describes this correctly. Test an independent full-state reference with mixed policies, explicit wide timestamp commands, expired automatic entries, pause/budget updates and concrete retained leases. Composite-key signed-second ordering and nanosecond/sequence ties need exact boundary tests. Prefix detach counts must include the precise disposition category, not merely removed cardinality. Counter/sequence overflow must fail before publication.

## Verification adequacy

The proposed full-handler plus CloseTransaction counters are necessary and materially stronger than prior decoded-byte tests. Include a clean-node visit counter, backing child-key iteration counter, component hydration count and task validation count so a lazy collection cannot pass by deferring the same O(N) walk to cleanup or EachPureTask. N=4/5/1000 and larger disabled-capacity tests must assert the same schema-derived maxima; wall-clock curves alone cannot establish them. Measure the first transaction after true cold reconstruction separately and require its hot processing bound.

Incremental spec evaluation introduces new named stutters and revision invalidation; existing finite Lean proofs do not automatically establish its equivalence. An update midway through union/exclusion preparation must neither publish a candidate from mixed definitions nor drop admitted old-generation request authority. Full output reads can be output-proportional, but cannot load unrelated historical blobs merely because the API returns running IDs. Detached nil-library readers must construct the same keyed layout without runtime config or handlers.

No implementation source or central ledger was edited. The architecture is suitable to proceed with instrumentation and narrow API/protocol specification. The five concrete contract points above remain review gates for the relevant implementation stages; this review does not certify their resolution.
