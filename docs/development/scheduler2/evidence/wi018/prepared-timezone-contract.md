# Prepared timezone adapter contract

Status: parent-approved design; steps1–3 implemented and awaiting independent review. This extends the unselected prepared-calendar prototype. No production named resolver, scheduler route, public restriction or migration is authorized by this artifact.

## Reference source and accepted input

Inspected local Go1.27.3 at /Users/alex/go/pkg/mod/golang.org/toolchain@v0.0.1-go1.27.3.darwin-arm64/src/time/: zoneinfo_read.go LoadLocationFromTZData (118 onward), zoneinfo.go lookup (149), lookupFirstZone (233), tzset (276), tzsetName/Offset/Rule/Num and tzruleTime (368–606), and time.go Date (1734). These are the executable semantic reference, including quirks; do not replace them with stricter POSIX/TZif interpretations.

The loader accepts TZif v1/v2/v3, skips the first32-bit section for v2/v3 and uses second-header counts, rejects missing zones and out-of-range byte indices, and reads offsets as signed32-bit seconds. It ignores leap corrections and standard/UTC flags for lookup. It does not sort or reject unsorted/duplicate transition timestamps. Empty transition input becomes one synthetic alpha/zone0 transition. Zone offsets can exceed24hours and move a supported UTC calendar boundary into a prior local year. Keep these offsets, order, duplicates and default first-zone selection; introduce no new transition/byte/year cap.

Go accepts some malformed-looking POSIX extensions by ignoring them: the extension is used only when its parse succeeds; failure falls back to the last selected TZif zone. A no-DST standard offset followed by a comma succeeds without parsing its remainder. Preserve this behavior. Parsing names, arbitrary input strings and all transitions is preparation work outside mutation.

## Prepared representation and ownership

Proposed immutable representation:

- Fixed header: schema version, transition count, precomputed before-first offset, first transition instant, fixed cache tuple (present/start/end/offset), parsed extension mode and fixed rule fields, fingerprint.
- Transition pages of16 entries, addressed by uint64 page ordinal. Each entry has signed64 transition instant and signed32 offset. The original positional array is preserved exactly. Inline offsets eliminate a second unbounded zone table lookup. DST/name fields are unnecessary for calendar instant/wall conversions once extension evaluation and first-zone selection are prepared.
- Fixed extension: invalid/absent, standard-only, or standard+daylight offsets; each of two rules is Julian/day-of-year/month-week-weekday with fixed integer fields and signed transition seconds. Name parsing is needed for acceptance and offsets but no name bytes are accessed by hot conversion.

Preparation clones input and owns its immutable header/pages. It computes first-zone selection using Go's exact precedence: unused zone0; nearest earlier non-DST zone before first transition's DST target; first non-DST zone; otherwise zone0. Scans happen once outside mutation. The implemented fingerprint hashes versioned exact source bytes plus the observable prepared cache tuple. This conservatively distinguishes semantically equal but byte-different inputs; it includes every conversion-relevant rule and ordered transition. Definition input identity remains separate, including exact custom bytes as already specified. Hashing and construction are input-proportional, never hidden in ordinary Advance.

The in-memory first implementation uses a private immutable page slice behind a reader interface with no exported mutable backing. A later CHASM adapter stores the same fixed pages in DataMap, fixed header in preparation control, and installs at most16 pages per quantum. Missing/corrupt addressed pages are errors with unchanged evaluation state, never synchronous source reload or fabricated offsets. Whole custom source/TZif reconstruction and named resolution occur outside mutation. A cache miss may suspend/retry preparation while retaining the original source revision; it may not silently fall back to time.Location during hot evaluation.

Persist the fixed header, fingerprint and installed frontier with the pages. Reload does not reseed its cache or reparse extension rules. Superseded page owners use the existing bounded preparation cleanup FIFO. A new source/refresh installs a new immutable version before switching; mixed-version page reads fail. The eventual evaluator and union/exclusion continuation compare resolved fingerprint and restart only unfinished work under the accepted refresh contract.

## Loader cache is observable for unusual transition arrays

Go's loader samples runtimeNow once and linearly selects the first adjacent transition interval containing that instant, then optionally substitutes an extension-derived cached interval/offset. lookup consults this cache before its binary search. For accepted unsorted arrays, this first interval can disagree with the binary-search result. Therefore discarding the cache is a semantic change; sorting transitions is also forbidden.

Preparation will take an explicit resolved-at instant supplied by the outside-mutation resolver, and reproduce this first-match cache scan and extension substitution. This is the loader's time input, not the execution clock or a new schedule deadline. Store the resulting fixed cache tuple and include it in the semantic fingerprint. Reload retains it. Repreparation may receive a different resolved-at instant, just as a fresh legacy LoadLocationFromTZData call can; if the cache semantics differ, the fingerprint changes and unfinished evaluation restarts. Even if ordered common-zone input happens to make cache tuples observationally redundant, do not elide them without proof covering Date's interval tests.

No reflection/unsafe access to private time.Location fields is proposed. Differential tests against independently loaded Go locations cannot assume their internal samples equal our chosen resolved-at value near a transition. Common fixtures must place the seed far inside a known stable interval, or compare regions outside the cache. Crafted unsorted/cache-sensitive fixtures must additionally assert the source-derived expected cache tuple and known outputs, with explicit chosen preparation instant. Report this evidence boundary; two nearly simultaneous loads are not proof of equal hidden seeds.

## Bounded lookup and conversion

lookup(seconds) exactly follows cache, before-first, then Go's indexed binary-search decisions. Use the same lo/hi midpoint and end tracking even on unsorted input; do not replace it with a sorted-array library search or scan. Count is bounded by the representable index width, not by a public transition cap: at most64 binary iterations plus fixed endpoint reads is a conservative ceiling (TZif's32-bit counts permit a tighter later bound). Each indexed access reads one fixed page and checks its ordinal/version/entry presence. If the selected index is last and extension parse succeeded, evaluate its fixed rules; otherwise use the selected inline offset/start/end. No operation scans zone names or transitions.

Instant-to-wall conversion performs one offset lookup, then adds the signed offset using integer seconds (not a duration that could overflow for extreme timestamps) and uses UTC-only Gregorian Date/Clock/Weekday arithmetic. UTC calls do not consult user timezone data. Inputs generated by the calendar are inside its source-supported range plus accepted signed32-bit offsets/carries; validate derived arithmetic bounds from that range rather than imposing a guessed local-year minimum.

Wall-to-instant must preserve time.Date: normalize month and subday fields, form the same UTC civil instant, lookup its offset/start/end, subtract the offset, and perform the second lookup only when adjusted UTC lies outside that interval. Do not use a generalized gap/fold solver. The calendar's corrected first-copy helper retains its exact one-hour comparison/addition semantics. All subsequent field extraction uses this adapter, never .In(userLocation) or time.Date(..., userLocation).

Rule evaluation preserves Go's Julian leap adjustment, day-of-year range0..365, M1..12.1..5.0..6 rules, default02:00, signed offsets and rule times with hours0..168 inclusive and optional minutes/seconds0..59 (maximum magnitude608399seconds), implicit US DST rules when names lack rule text, semicolon alternative before first rule, southern-hemisphere swap including offsets, and the returned year-bound intervals (including Go's365-day terminal bound). Names may use angle brackets; numeric/name scans are preparation-only. Rule calculation is fixed arithmetic plus at most4 week increments. Match the reference's year/day and negative-epoch remainder arithmetic, rather than assuming modern positive timestamps.

Errors from any page access leave the incoming continuation unchanged, including when a second lookup fails after the first succeeded. An Advance call uses a local state copy and publishes only after all its bounded steps succeed. Stats must count actual lookup calls, page reads, fixed entries inspected and encoded bytes. Derive a final maximum from the adapter implementation: the planned calendar normalization performs at most8 lookups (two first-copy Date conversions and their wall-field checks); multiply by the fixed indexed lookup bound. This is a design ceiling, not yet measured acceptance evidence.

## Named resolver boundary

This adapter consumes actual resolved TZif/prepared input. It does not replace named resolution with GOROOT-only lookup. Later named resolver integration must preserve Go's ZONEINFO, system paths, GOROOT zip and embedded tzdata source order, UTC/empty/Local special cases, and existing SpecBuilder cache refresh semantics. Local is not silently UTC. A loaded *time.Location plus a name hash remains insufficient to reconstruct exact rules. The first implementation supports explicit custom TZif and known resolved snapshots; production named resolution remains an explicit gate.

1. Implement pure TZif parsing/preparation and fixed extension parser/evaluator using source-derived semantics; record Go source fingerprints and license attribution if adapting code. No evaluator switch yet.
2. Implement immutable page reader, offset lookup and UTC-only wall/instant conversion with operation counters and page fault injection. Compare against Go on normal fixtures, known DST outputs and selected custom byte constructors.
3. Replace prepared-calendar conversion calls with adapter methods, propagate errors without advancing state, and rerun its known DST, nonvacuous reference, budget partition, horizon and refresh gates. Keep the old capability only as an explicitly unbounded reference fixture if needed; do not offer an unnoticed hot fallback.
4. Independently review then add persisted page/header installation and refresh integration. Actual full CHASM transaction counts, source lifecycle/cleanup and nil-reader behavior are separate acceptance gates.

Differential matrix: v1/v2/v3, empty transitions, all four first-zone cases, duplicated/unsorted timestamps, alpha/omega boundaries, signed32 offset extremes and non-hour offsets, ordinary/fractional/negative/greater-than24-hour DST transitions, Northern/Southern zones, extension invalid fallback, standard-only and explicit/implicit DST, J/day/M rules including fifth weekday/leap year, long quoted/unquoted names, and truncated/rejected input parity. Evaluate first/before/at/after/last transitions plus Date gaps/folds and supported boundary years. Assert exact offsets and Date outputs, not only successful parsing. Growing transition counts must retain the same page/read ceiling. Corrupt/missing every addressed page in turn, repeat after serialized continuation reload, and preserve original state on failure. Broader accepted inputs without exact source/test coverage remain open rather than silently rejected.
