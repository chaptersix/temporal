# Queue runtime integration: exact bounded replacement

Owner: framework_finish; proposal for root source assignment. Source baseline94aa3a263 plus the in-progress SequenceIndex/backend capability. This is an implementation map for replacing the actual public scheduler queue path, not acceptance of another standalone queue prototype. Framework source remains frozen. No migration of existing executions or production routing is proposed.

## Storage schema and ownership

Add a fixed `QueueState` field to RootState for the new local public profile, and two DATA collections on Scheduler: `QueueRecords DataMap[*QueuedOccurrence]` and `QueuePages DataMap[*commonpb.Payload]`. Existing RootState.Queue remains solely for the finite/reference profile. A persisted format selector makes the two representations exclusive; reject a mixed image rather than silently synthesizing empty indexes or rebuilding on an ordinary mutation. Newly created public-profile schedules select the indexed format once the complete vertical slice below is ready. Old finite test records keep their decoder. The local test environment can create fresh records; this work does not migrate existing executions.

QueueState fields:

- `next_sequence uint64`, initially1, with explicit exhaustion before append; sequence0 is reserved.
- `active_generation uint64`, initially1, and `next_generation uint64`; generations are never reused while physical state may remain.
- Six explicit int64 logical class counters: automatic ordinary/cancel/terminate, explicit ordinary/cancel/terminate. Total is their fixed six-term checked sum. Ordinary includes every concrete non-effect policy; preserve the policy in the record.
- Optional `completed_drain` descriptor containing source generation, maximum source sequence, remaining physical source count, next source sequence plus class, immutable automatic-enabled flag and exact12-byte threshold, first-eligible sequence/class, selected sequence/class, and selected-present bit. The descriptor is at most one fixed record, not a list. Persist original logical removed/missed/superseded totals for diagnostic/refinement checks; do not apply them again during cleanup.

The source-generation record count and logical totals are distinct. A global record is keyed by fixed-width sequence; its concrete policy, timestamps, command IDs and workflow identity are unchanged. Generation ownership resides in the six indexes, not a duplicate generation field in each record. Moving a survivor keeps its record key/bytes unchanged. A removed record is physically deleted only during source maintenance. An admitted operation/request owns its new independent issuance metadata; selected queue records own no frozen request blob.

A SequenceIndex ID is16 bytes: big-endian uint64 generation, one class byte0..5, remaining bytes zero. Index agent confirmed the identifier is opaque and this encoding is supported. CountBatch performs all six class queries, point moves and owning-root writes in a shared overlay. indexBackend binds that overlay to QueuePages in the same CHASM transaction as QueueState/QueueRecords. Never reuse an active or source generation ID. Root/descriptor overflows, record-key collisions, invalid counts and source membership mismatch fail before any publication.

## Runtime queue facade and exact queries

Implement `queue_state.go` in scheduler2 with these methods (names may follow local conventions):

- `queueSummary(ctx)` returns the fixed logical class counts and whether a completed drain is pending, without reading QueueRecords/QueuePages. Finite mode derives its summary from the finite reference slice.
- `planQueueDrain(ctx, controls, now, catchup)` returns a value-only QueueDrainPlan and one selected QueuedOccurrence when applicable. It never mutates. Controls include blocking operation, paused/limited/remaining and operation availability. During a pending descriptor it reports maintenance-deferred, never reinterprets the old predicate.
- `stageQueueAppend(ctx, queued)` validates/prepares one record insertion and one class index update into the active generation. A transition can append at most one queue record.
- `stageQueueDrain(ctx, plan)` prepares a fresh empty active generation and the completed source descriptor, updates the six logical counters, and does no rectangle deletion.
- `maintainQueue(ctx)` handles exactly one source record, shared-batch point insertion into active if it survives and deletion from source, then record deletion only if already logically removed. It updates remaining/cursor or clears the descriptor on the last record.
- `queueProjection(ctx, visit)` is explicit output-proportional traversal for tests/offline inspection only; no handler or validator may invoke it. Required public Describe currently returns running operations, not the full queue, so it does not need this traversal.

For each eligible class c, `E[c] = SequenceCount(index(c),0,MaxUint64,lower(c))`; lower is all-zero for explicit, the exact automatic threshold for enabled automatic, and disabled automatic contributes0 without a query. Query first across the six first extremes, and last effect across the four cancel/terminate last extremes. Selection is last effect when present, otherwise first eligible. The fixed generation maximum comes from class tails or a persisted last-admitted sequence; it must include only the frozen generation.

If blocking operation is set, no drain. Negative catchup remains an error. If all eligible counts are zero, remove every logical queue member even when operation capacity is unavailable. Otherwise insufficient operation capacity returns unchanged with no descriptor. With selected sequence s, for each class:

`removed[c] = physical[c] - E[c] + eligible_effect_prefix[c] + selected_in_c + first_ordinary_predecessor_in_c`.

The effect prefix is an inclusive range count0..s-1 for effect classes only, with their current eligibility threshold; s>=1 avoids underflow. First-ordinary predecessor contributes1 only if first<s and its policy is ordinary. A first effect predecessor is already in the effect-prefix count. Superseded is the sum of effect-prefix counts plus first-ordinary predecessor. Retained logical counts are physical-minus-removed. Missed catchup is the disabled-by-threshold automatic count only when automatic is enabled and an actual drain disposition occurs; paused/limited invalidation does not increment missed. The selected record's exact Actual timestamp supplies public action timing, eliminating the later public DrainIndex scan.

Construct the threshold by exact seconds/nanos arithmetic (`time.Unix(0,now).Add(-time.Duration(catchup))` within the existing int64 now/catchup domain, then encode NewTimeKey's first12 bytes); do not compute now-catchup in int64 nanoseconds where it can overflow. Explicit entries never use their nanosecond placeholder for eligibility. Query counts are uint64 internally; checked conversion and sum must fit persisted int64 control/public counters before writes.

## Decision seam: preserve the finite reducer as oracle

Add a value-only `decision.QueueSummary` and an optional indexed-queue flag to State, not an interface that hides I/O in decision.Step. Summary includes logical counts and maintenance-deferred. Add `QueueLength`, `QueueEffect`, and an append helper used by existing decision paths. In finite mode these retain the existing slice behavior. In indexed mode they use fixed summary values; clone copies values, never a queue slice.

Decision.Step returns an explicit queue change alongside its control changes: none, one append, or a supplied completed-drain plan. For append, update fixed summary/class counts and retain the single Queued value for publication. For drain, scheduler supplies a prevalidated value plan in the internal Event with selected candidate, retained counts and disposition counts; Step applies the same startOperation helper exactly once. This plan is internal, never accepted from public RPC input. Validate its source generation/control revision against the state built in the same transaction. No fabricated miniature queue may stand in for the real queue: it would lose effect/capacity counts and change supersession.

Keep existing slice `DrainIndex`, drain and clone paths intact as the independent reference. A differential suite compares full projected queue, selected operation, budget, counters and effects after every event, including maintenance identity stutters. The new summary path must not call the slice oracle in production. A final source search enumerates and classifies every `.Queue` access; only finite mode and explicit reference/export code may retain slice iteration.

## Maintenance, cursor and coordinator lease rules

The descriptor stores the exact next source sequence/class. At publication compute it from the minimum across six source indexes. On each maintenance call, verify that addressed record and exact source membership exist; evaluate the frozen predicate using sequence/class/time only. Atomically move survivor membership or remove dead record, delete old membership, decrement remaining, then compute the next minimum across the six source indexes. There is no loop over missing/dead sequence numbers. On remaining0, all source indexes must be empty; clear descriptor without walking/releasing a bulk root. Any empty/remaining disagreement fails closed.

`executeWorkQuantum` performs at most one maintenance record before its ordinary selected quantum. Maintenance must not rotate NextWork/NextOperation/NextQueue or clear OwnerKey. A drain demand during debt is present-but-deferred; other manual/backfill/automatic demands remain eligible under current logical counts. Preserve concrete vacancy owners across maintenance. On the quantum that empties debt, recompute demands and permit a new drain using the then-current controls/time. New arrivals always append to active generation and cannot increase source remaining.

When only debt is runnable, reconcileWork arms the existing fixed WorkTask at execution time and executeWorkQuantum runs maintenance even if normal planWorkFor returns no selected demand. Its existing token/incarnation validation fences stale deliveries. Charge maintenance within each of the existing maximum-two immediate coordinator quanta; do not install an unbounded immediate chain. Subsequent physical WorkTask rearming must remain guaranteed when debt persists after the immediate budget. Test existing work-token exhaustion and idle-close boundaries with debt before choosing an additional task type; prefer no new task type unless the current coordinator cannot provide this continuation.

Successful maintenance reduces finite source remaining by1 even under sustained arrivals/updates. This is the named finite delay before a later drain, not a fixed latency or grant-count promise. Controls can change future drain decisions but never rewrite the completed predicate. Root close/recreation fences maintenance through existing incarnation/closed/token checks and leaves DATA for execution retention; no eager owner scan.
