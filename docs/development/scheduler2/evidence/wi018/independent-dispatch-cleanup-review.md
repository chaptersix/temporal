# Independent dispatch/cleanup review

Reviewer: api_seam. Reviewed root's dispatch-cleanup-contract.md against actual StartHandler/EffectHandler, physical History task executors and client wrappers. No runtime changes or acceptance claim.

The protocol correctly separates durable operation authority from transient dispatch ownership, keeps positive evidence independent of claim expiry, and fences stale failures from rescheduling a newer claim. One Start and one effect slot preserve the existing separate handler permit classes. Cleanup retains closed DATA for existing deletion, avoiding an unsupported assumption that ordinary scheduler tasks continue after closure. Running cleanup FIFO descriptors are keyed and root-sized, with their reference ownership retained until atomic cursor disposal; this is compatible with bounded per-step work while honestly permitting storage backlog.

## Concrete timeout source

Both `transfer_queue_active_task_executor.go:executeChasmSideEffectTransferTask` and `timer_queue_active_task_executor.go:executeChasmSideEffectTimerTask` call `context.WithTimeout(ctx, taskTimeout)` before load and task execution. `transfer_queue_task_executor_base.go` defines taskTimeout as **3 seconds × debug.TimeoutMultiplier**. `common/debug/not_debug.go` sets multiplier1; debug.go sets100. `chasm_task_util.go` carries this same context through ExecuteSideEffectTask. It covers lock acquisition, local permit wait, request snapshot, actual client and result merge.

Frontend `client.go` defaults10seconds and History defaults30seconds, but their calls are children of that parent deadline; retry wrappers call ThrottleRetryContext on the parent. Those per-attempt defaults must not be mistaken for the overall claim lifetime. Existing injected callbacks must honor context; Go cannot forcibly stop an arbitrary callback ignoring cancellation. Such callback non-cooperation is a trusted transport boundary, not solved by adding a timer.

Recommended concrete contract: acquire the existing local resource permit, then claim under the remaining bounded physical task context. Snapshot its deadline and convert remaining wall duration into an execution-time recovery wake using the same clock/skip snapshot discipline as existing issuance. Fail without publishing a claim when no positive duration remains. Do not persist raw wall-clock expiry or silently invent a client timeout. A narrow test/runtime dependency can expose the existing task timeout if needed, but the actual context deadline is authoritative and may be earlier. Exact expiry can coincide with caller deadline: duplicate issuance around that boundary is already allowed and fenced; an arbitrary extra margin is not required for safety. Clock skipping may expire a claim earlier, so its safety must not depend on expiry being later than the RPC's wall completion.

## Required implementation details

- Acquire the permit before claim publication. Otherwise a claim can expire waiting for a global local permit without ever getting an issuance chance; recovery still works, but creates needless churn and weakens fairness evidence. No lock is held while waiting on the permit or calling RPC.
- A known successful response arriving with an expired context may fail to commit its reconciliation. Preserve operation authority and allow ordinary retry/callback recovery; do not claim every observed successful return commits immediately. If a separate bounded reconciliation context is introduced, specify its scope and failure behavior explicitly rather than dropping cancellation silently.
- Late success addresses its original operation, removes only that operation's ready entry, and may clear the slot only if slot identity/generation still matches. Late failure cannot change a newer claim's expiry/wake. Callback settlement applies the same addressed-slot guard.
- Reinsert at execution-now with a new monotonic fairness sequence, not at the original old ready time, and define index tie ordering exactly. New arrivals use current ready time rather than historical nominal occurrence time. This is necessary for the stated finite-waiter fairness argument.
- A scheduled recovery wake is durable before the snapshot becomes externally issuable. Failure after claim commit but before returning snapshot is an explicit recovery case. Claim and index publication must be one transaction; context expiry must not leave a removed ready entry without recovery.
- A fixed slot cannot suppress callbacks or unrelated coordinator service while its RPC is pending. Test slow Start alongside effect, callback-before-release, then a new operation, including expiry/late-result crossing.
- Cleanup descriptor append, subtree detachment and occupancy/disposition counters are atomic; cleanup cursor advancement and refcount decrements are atomic. Count cursor-stack/page inspection as well as removed records. Closed-root bytes are intentionally retained; generic execution deletion cost is a separately reported lifecycle/cold boundary, not a hidden ordinary mutation scan.

With these details, the proposal is suitable for implementation and the listed fault witnesses. Fixed task counts, queue fairness, total bytes and nil-library decoding remain unproven until implemented and independently tested.
