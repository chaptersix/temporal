## Findings

No blocking semantic defect found in the reviewed module.

1. `loop_ticks_irrelevant` proves structural recursion ticks are irrelevant above the actual remaining rank. It inducts on ticks and explicitly proves rank decreases on pending disposition and raw probing. `run_unfold` therefore exposes the real executable transition, rather than postulating a new evaluator equivalent to it.
2. `run_probe_resume` preserves the full Result via `joinResult`: the second machine and stop, concatenated outputs, and summed probes. The first call must actually yield, matching the original conditional resume obligation. The only additional cache condition excludes an input terminal cache equal to Yield; public validState disallows that class. The induction handles excluded dispositions without consuming output slots, eligible dispositions with one fewer residual slot, and raw probing with one fewer fuel. The terminal probe cannot be mistaken for Yield. No output/state equality is assumed.
3. `complete` is a well-founded, resource-free normal form of the same transitions, including lookahead/pending and terminal cache. `run_sufficient_exact` proves equivalence from numeric resource bounds (rest length < probes; remaining length < output slots). It does not assume completion, a final empty suffix, or a desired state.
4. `complete_batching` inducts over the finite remaining rank and checks the critical future-pending branch: the earlier call waits without disposing it, then the later call resumes from that exact machine. The monotone endpoint requirement is explicit. Whole Result equality entails every public state field and exact final status/probe accounting, not just occurrence-sequence equality. No source actual-order hypothesis is needed for this execution-to-execution equivalence; actual ordering is separately needed to interpret output as the independently filtered calendar stream.
5. `run_window_batching_uniform` provides concrete remaining-length-plus-one resources; the original raw-length-plus-one sufficient budgets are covered by the more general `run_window_batching_exact` bounds. `SufficientWindows` gives per-call endpoints/resources without assuming the desired result. The finite theorem's final complete/run call supplies the actual last stop; it does not confuse the intermediate resume fold's terminal-summary stop with a public response.
6. `disposedTrace` recovers the unique consumed raw prefix from before/after remaining suffixes. `run_disposedTrace_spec` obtains its premise from the actual loop suffix theorem; it is not a caller-provided disposition equation. Composition follows list suffix cancellation, and probe-resume equality transfers the exact final machine. The trace includes excluded and eligible candidates with their revision/identity fields. Applying eligible to the trace specification and comparing with run_conservation yields that eligible trace equals emitted output by suffix cancellation; excluded/emitted journal kinds are therefore recoverable from preserved candidate flags. This is an explicit ghost accounting trace, not a claim that the executable API exposes a journal field.
