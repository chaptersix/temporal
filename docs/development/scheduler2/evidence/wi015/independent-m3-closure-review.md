## Bounds, authorization and proof limits

The near-2MiB input/result/failure experiment does not prove arbitrary accepted payload combinations can start: the combined roughly6.24MiB Start RPC exceeds the existing4MiB gRPC receive ceiling. Its positive roughly3.75MiB profile and negative retained-authority profile are useful distinct evidence. Preserve that transport limit and D59-E1 conditional progress assumption; no acceptance may relabel retained ambiguity as successful execution. Shared immutable payload storage reduces duplicate state bytes but does not establish an aggregate8MiB mutable-state guarantee across arbitrary distinct generations. M4 must measure that growth without raising limits.

Public spec acceptance now removes prototype64KiB/64-term/1024-range ceilings. Existing frontend input/memo blob limits do not directly bound spec size. A bounded probe count therefore is not a constant CPU bound independent of spec complexity. Public timestamp syntax can accept years1..9999 while reference enumeration retains its existing nominal horizon and physical wakes retain the supported execution-clock domain. The timestamp review explicitly documents this and does not claim arbitrary-century clock support or wide-domain Lean proof.

Authorization evidence is meaningful for its stated scope: all eight actual frontend Schedule operations receive denial before the selected backend counter can increment, with ordinary allowed setup and restored authorizer. Typed/persisted identity, isolated List/Count and no fallback are established separately. There is no basis to demand production routing as an authorization test, or to claim the deny fixture alone proves successful backend identity.
