# Combined clock skip, reload and physical timer consumption

The new dedicated local test captures a real persisted scheduler2 pure-timer envelope before a10s virtual-clock skip. Its first daily logical tick is20s ahead. It observes the shifted physical envelope, closes the History shard, reloads the same typed scheduler2 execution, and re-enqueues the original physical envelope through Admin.AddTasks. The original supplied physical timestamp, execution identity and archetype are unchanged. The shard assigns a new task ID and advances millisecond precision; the witness explicitly permits only2ms around the original physical timestamp when binding that new recorded task.

Before and after the skip, the persisted logical WorkTask is byte/proto equal in type, payload/token, logical deadline, versioned transition and transition offset; only the cluster-local PhysicalTaskStatus is excluded from that comparison. Reloaded coordinator.Token must equal the original serialized WorkTask token. This is a physical clock restamp of the same logical obligation, not a test that merely invalidates an old generation token.

Two independent dedicated-cluster cases enforce causal ordering using the actual HistoryTimerTaskInterceptor:

- **shifted_first:** gate the shifted envelope before its real executor call; require zero public actions/recent results and zero workflow-body executions; release it and require exactly one action at the original nominal tick with no premature actual time. Then observe actual execution of the explicitly re-enqueued old physical envelope; public action count, recent identity and workflow-body count remain one.
- **old_physical_first:** gate both the shifted envelope and the original still-queued envelope. When the explicitly re-enqueued old envelope reaches actual dispatch, verify the original logical token is still live and no workflow has run. Let that old physical stamp service the due logical obligation once; then release and observe execution of the shifted duplicate, with no additional action. This case avoids attributing success only to token supersession after the shifted timer already completed.

The hook invokes the real active/standby executor closure; it does not call WorkHandler directly, fabricate a logical task, replace the executor response, or claim a mock validation result. Public API state, actual worker execution count, typed/persisted scheduler2 identity, successful persistence task writes and physical dispatcher observations jointly establish the witness. HistoryTaskRecorder records after successful persistence delegation. It is not a universal proof of every queue retry ordering or a query of the timer queue's final ack watermark.
